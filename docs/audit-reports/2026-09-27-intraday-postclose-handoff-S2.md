## 4. S2 인계·자체 검토

- S6 수리 묶음: **AI trace→outcome/label** `S2-ENT-01`; **sizing plan→owner/BUY terminal** `S2-ENT-02`·`03`(같은 attempt/주문 분모를 먼저 고정); **route-bound quote clock→pre-submit reader** `S2-ENT-04`; **순차 첫 BUY receipt→cancel-wait reader** `S2-ENT-05`(변경형 활성 전 계약 선택). 각 묶음은 원천 1행·부분체결·취소·불확실 응답 fixture와 기존 hard guard를 유지한 회귀를 닫힘 검사로 삼는다. `S1-COM-01-A` scanner 압축본 reader는 별도 S6 묶음 유지.
- S3는 BUY 체결 후 보유·SELL·실현 비용, `S0-EXIT-01`과 `S1-COM-03-A`의 두 건의 비용/venue gap을 받는다. S4는 widget/episode prospective micro gap 등 별도 owner를 분류한다. S5는 stage 이후 strict/finalizer/PREOPEN과 현재 수량 정책의 새 exact-date handoff·PID 소비를 대사한다.
- 현재 `current.json`/v2 파일은 **선택된 파일 상태**, 순차 형상은 전부 parent이며 새 bundle 자연 원천은 `not_observed`다. 9/28 bootstrap 파일은 9/26 생성된 이전 세대이고 수량 env 키가 없어 새 릴리스 PID 소비 증거가 아니다. 기존 안전·operator veto·수량 cap/계좌·broker·source-quality guard를 변경하지 않았다. AVG_DOWN/PYRAMID와 SELL 경제성은 이번 조사 결과에 섞지 않았다.
- 원천→reader의 stage/registry/AI ID 분모를 재대사하고, 소스 코드의 조건부 branch와 보고서의 `source_gap`, `incumbent_carry`, `source_quality_blocked`를 구별했다. 이 문서는 read-only 진단과 보고서 작성만 수행했다. 링크·owner·권한·print-only parser 및 `git diff --check`로 문서를 검증한다. 정규 장후 실행, provider 호출, bot 재시작, 주문, 정책/서비스 변경, 대용량 raw 재스캔은 수행하지 않는다.
