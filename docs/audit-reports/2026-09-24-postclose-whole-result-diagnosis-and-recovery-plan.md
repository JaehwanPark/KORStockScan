## 3. 계산 시간 해소 순서

1. **측정·중복 제거:** 9/23 immutable source와 실행 release별 동일 input/prerequisite/code hash를 고정한다. child 단위 wall/CPU/RSS/swap/I/O, source 대기, resource admission, retry, cache hit를 구분한다. 이미 성공한 stage는 hash가 유효할 때 재사용한다. 20:10 이후 약 9시간의 monitoring wall을 독립 계산 시간으로 쓰지 않는다.
2. **Main full evaluator 우선 최적화:** `src/engine/scalping/ai_action_outcome_calibration.py`의 `_common_refinement_population`은 각 paired/natural 행마다 `operating_projection.rows` 전체를 선형 검색하고, natural 행마다 projection 전체를 serialize/hash하는 `compact.valid()`를 호출한다. 이어 sequence group마다 `natural_rows`를 다시 순회한다. 9개 scope가 같은 natural 원천을 사용한다. 이는 확인된 반복 계산 구조이며 전체 86분의 기여율은 아직 미측정이다. projection 검증 1회, exact attempt ID 인덱스와 중복/충돌 규칙, sequence key 인덱스를 기존 함수 안에 적용하고 캐시 무효화 키를 source/code/schema/cost/label로 고정한다. 원 순서·제외 사유·hash·정책 결과가 같아야 한다.
3. **Widget / episode / I/O:** 기존 [품질 보존형 최적화 계획](../proposals/postclose-long-running-work-quality-preserving-optimization-plan-2026-09-23.md)의 EOD 대기 compute slot 분리, symbol-local 재사용, episode fast-reference 및 이전 rising 단일 read 수정을 실제 선택 release와 비교한다. 이미 반영된 변경을 다시 구현하지 않는다. 동시 대형 worker는 기존 두 compute slot 안에서 resource sample에 따라 배치한다.
4. **필요할 때만 대상 축소:** 최적화·스케줄 조정 후에도 측정된 critical path가 마감 시한을 초과하면, 기존 widget 100·episode 신규 탐색 50 한도와 안정적 사전선정 규칙을 우선 이용한다. 운영·watch·기존 episode 평가와 필수 source/holdout은 유지하고 deferred census·사유·다음 실행 owner를 기록한다. Main full-population 정책이나 paired denominator를 몰래 잘라 승격하지 않는다. 필수 모집단을 줄여야 한다면 비교/승격을 차단한 연구용 범위로 명시하고 incumbent carry로 발행한다. 적절한 범위는 고정 원천의 품질·시간 측정 후 결정한다.
