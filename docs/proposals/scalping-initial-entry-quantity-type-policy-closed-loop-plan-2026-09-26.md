### 변경하지 않는 소유권

- `AVG_DOWN`은 기존 [`sniper_scale_in.py`](../../src/engine/sniper_scale_in.py)의 별도 action·price·execution-sizing 소유자이며 원진입 시점의 공식·tier를 재사용한다. 회복불가한 원진입 문맥은 10% 보수 경로 또는 차단 사유로 남긴다. `PYRAMID`의 수량 0/퇴역 상태는 복구하지 않는다.
- 분할 다리·leg 가격의 실행 소유권, probe-first 1주, 제출·체결·잔량, AI·기계 진입 판정, 수동/widget/episode 소유권을 최초 총수량 allocator에 넘기지 않는다. 장후에는 수량×분할을 **공동 평가**하고 단일 정책 세대로 결속한다. `target_qty`, `planned_leg_qty`, `submitted_qty`, `filled_qty`, `residual_qty`를 서로 다른 필드로 기록한다.
- 기존 Plan Rebase의 고정 5단계와 NXT/원천 결손 tier 1, 25% 최대치, 95% 안전 예산 및 하위 상한이 승인된 기준이다. 현재 §5는 결합 challenger에 원본 4조합 근거를 요구하므로, **완료 거래 기반 초기/갱신 v2 근거 경로를 실제로 활성화하기 전에** 해당 소유 계약과 현재 실행 체크리스트를 일치시킨다. 이 문서만으로 새 tier/분할 정책을 활성화하지 않으며 하드 안전·운영 잠금은 유지한다.

## 2. 퇴역·중복 코드 제거 순서

1. **도달성 명세부터 고정:** `src/run_bot.sh` → 실제 메인 엔트리 → 최초 수량 allocator → 주문 계획/최종 가격 재검증, `deploy/run_threshold_cycle_postclose.sh` → 보고서, PREOPEN bootstrap → 선택 릴리스/PID의 호출 그래프를 만든다. 상수·환경변수·CLI·정책 스키마·테스트·과거 영수증을 `active / compatibility-read / report-only / unreachable`로 분류하고, 코드 경로별 소비 테스트를 붙인다. 파일명이나 주석의 `deprecated`만으로 삭제하지 않는다.
2. **삭제 후보:** 중앙 allocator의 수량을 결정하지 않는 `INVEST_RATIO_SCALPING_MIN/MAX` 및 `src/run_bot.sh` 기본 export는 실제 읽기와 simulator·설정 테스트를 대사한 뒤 제거한다. 과거 정책의 `ACTIVE_DATE == today` 검사와 날짜별 파일명을 찾는 **수량 런타임** 경로는 v2 수용 뒤 제거한다. 퇴역 `PYRAMID`의 수량 후보 생성·그리드·실행 불가능 branch가 실제로 호출되지 않으면 제거하되, 기록 해석용 `pyramid_permanently_retired` 사유는 유지한다. 복제된 예산/수량 계산이 있으면 중앙 allocator와 최종 가격의 감액 재검증으로 수렴시킨다.
3. **삭제 금지 경계:** AVG_DOWN 원진입 고정값, 장중 최종가 감액, probe-first 운영 override, 수량 보존 validator, 역사적 v1 정책 읽기·감사, 재생 분석의 호환 parser는 도달성 증거 없이 제거하지 않는다. 기존 불변 artifact는 삭제 대상이 아니다. 런타임의 오래된 읽기 경로를 제거해도 역사적 보고서의 해시와 해석은 보존한다.
4. 각 삭제 묶음마다 기존·신규 동일 입력에서 `effective_qty`, reason, 안전 상한, 주문 계획이 같은지 확인한다. caller 0, 테스트/CLI 이전 완료, 선택 릴리스 영향 없음이 증명된 묶음만 삭제한다. 새로운 Python 파일이 필요하면 먼저 위치 게이트를 수행하고 `src/engine/scalping` 또는 `src/engine/automation`의 기존 소유 모듈을 우선 사용한다. `src/engine` 루트에 새 모듈을 만들지 않는다.

## 3. 런타임 생산자와 유형 후보

**생산 시점:** `sniper_state_handlers.py`가 같은 exact entry attempt에서 최초 총수량을 결정할 때 판정 전 snapshot을 봉인한다. 최소 필드는 source date/time KST, attempt·scanner promotion·stock·main owner, 유효 거래소/세션 및 route/epoch, 가격·tick, 출처 signature/count, 가용 예산과 적용 상한, 사용된 정책/부모 hash, 선택 유형/tier, `pre_cap_qty`/`effective_qty`다. 분할 계획과 최종 제출 전 재검증은 같은 attempt에 연결하되 미래 체결이나 비용을 유형 판정에 주입하지 않는다. 거래소·시간·출처 결손은 기존 보수 tier를 유지한다. 서로 다른 route나 stale/conflict 호가는 상위 안전 가드의 차단을 보존하며 수량 유형의 10% 허용으로 바꾸지 않는다.

[`entry_setup_evidence.py`](../../src/engine/scalping/entry_setup_evidence.py)의 `build_entry_predecision_group_observation`은 이미 가격 대비 tick(`LT_5BP`, `5_TO_10BP`, `GE_10BP`), 호가 유동성(`SUPPORTIVE`, `BOUNDED`, `FRAGILE`), 완료봉 변동성(`LOW`, `MEDIUM`, `HIGH`), 구조 단계, venue/session을 계산한다. 현재 이 관측물은 `runtime_effect=false`인 보고용이다. **공통 순수 feature 함수와 판정 시점 provenance를 분리**해 런타임 수량 producer와 장후 evaluator가 동일 계산을 사용하도록 만들되, 이 보고용 객체 자체를 승인 정책으로 읽지 않는다. 매매흐름 축은 기존 trusted signed aggressor/OFI 관측의 사건 시점·route/epoch·신선도·표본수를 검증한 경우에만 확장한다. 시가총액은 당시 시점의 출처가 검증되기 전에는 분류에 쓰지 않는다.

| 후보 유형 | 판정 전 특징과 초기 제안 | 정책 승격 범위 |
| --- | --- | --- |

시장 상태가 필요하면 기존 venue/session과 완료봉 구조를 우선 사용한다. 외부 지수/시가총액 새 fetch나 별도 AI 호출은 추가하지 않는다. **전 축 직교 조합을 정책 수로 만들지 않는다.** 우선순위 `SAFE_UNKNOWN → 유효 venue/session 부모 → 한정된 위험/유동성/흐름 leaf`를 고정한다. 분기 정의, UNKNOWN 처리, 중복 유형 우선순위, 분류 버전은 진입 판정 전 시점에 동일하며 최초 후보 탐색에서 고정한다. 각 leaf는 고유 완료 거래·날짜·원본 attempt 수와 부모 대비 노출 비율을 보고하고, 체결 후 가격 경로가 부족하면 부모 carry한다. 유형별 ratio는 우선 기존 {10, 15, 20, 25}% tier 선택 범위로 제한한다. 범위 확대는 별도 정책 변경이다.

| `all_completed_initial_trades` | 위 기준으로 봉인한 **전체** 고유 실거래 종료 집합. 최초 생성의 원모수이며 실제 비용 후 PnL/승률과 유형 분포의 분모다. 원본 plan/4조합 영수증의 존재 여부로 줄이지 않는다. |
| `post_fill_path_supported` | 원체결 이후부터 정해진 leg 대기 한도와 실제 청산 전까지의 같은 종목·시장·경로·세션 가격/호가/체결 자료가 시각 순서대로 연결된 거래. 결손 거래는 원모수에 남기고 `path_source_gap`으로 센다. 저가만 있으면 `price_touch_only`다. |
| `candidate_fill_scenarios` | 고정된 원거래에 가상 분할 지정가를 놓고 관측 가격이 지정가 아래까지 내려간 시각·거래량을 확인해 **그 가격에 체결되었다면**의 조건부 fill을 만든 후보×거래. 지정가를 한 번 터치한 경우, 호가·대기열·거래량이 없는 경우에는 체결 확정으로 쓰지 않고 보수/중립/상방 fill 시나리오와 불확실성으로 분리한다. 검증된 미도달/무체결과 `fill_unknown/censored`를 구분한다. 최초 생성에 완전한 주문 대기열 영수증을 요구하지 않는다. |
| `paired_net_comparable` | 같은 원거래·유형에서 실제 체결 성과와 후보의 조건부 체결/검증된 무체결·부분체결, 놓친 원거래 이익/손실, 수수료·세금·슬리피지·자본 노출 및 **실제 청산 영수증을 고정한 조건부** 결과가 결속된 쌍. 가격 미도달 거래를 제외해 후보 EV를 높이지 않는다. 실제 PnL과 대안 **추정** PnL을 별도 표시한다. 최초 선정은 이 집합의 유형별 비용 후 추정 EV와 fill 가정 민감도로 하고, coverage=`paired_net_comparable / all_completed_initial_trades` 및 결손·검열 수를 함께 보고한다. |
| `all_initial_sizing_attempts` | 최초 진입 수량 결정 전수(미제출/미체결 포함)는 런타임 적용률·선택편향·기회비용 감시의 별도 모수다. 아직 종료된 실거래가 아닌 시도를 최초 학습 PnL에 합산하지 않으며, 갱신 시에는 실제 적용 정책의 무체결/잔량 결과까지 별도 평가한다. |

현행 [`strategy_owner_replay.py`](../../src/engine/scalping/strategy_owner_replay.py)의 4조합 분모는 유효한 원본 plan/frozen seed의 `unique_retained`이므로 9/23처럼 전부 0이 될 수 있다. 이를 **최초 정책 생성의 전제에서 제거**하고 후속 검증/진단용으로 유지한다. 기존 [`entry_split_order_plan.py`](../../src/engine/scalping/entry_split_order_plan.py)의 `post_submit_low_tick_bands`는 제출 이후 저가 터치 통계이므로 체결 이후 경로·체결 가능성·후보 EV와 혼동하지 않는다. 완료 거래의 원모수 → 원체결 결속 → 체결 후 경로 → 후보 실행 가능성 → 쌍비교의 각 단계에서 동일 ID의 보존식, 제외/검열 사유, 누락 비용을 보고한다. 원모수 전체를 좁은 가격 경로 가용 집합으로 조용히 바꿔 정책을 발행하지 않는다.

1. **원천 전체 수집:** 기존 실거래 post-sell 완료/비용 영수증을 최초 진입 fill·owner custody·정책 세대에 결속하고 클린 베이스라인 이후의 **가능한 모든** 종료 거래를 일괄 열거한다. 기존 `real_ev_values`의 배열 길이를 고유 거래 수로 쓰지 않고 position/entry episode를 중복 제거한다. 주문 이후 가격 통계 producer는 재사용하되 기준 시각을 실제 최초 fill로 바꾸고 이후의 원시 체결·호가/depth를 동일 route/epoch에서 연결한다. 미보유·비완료·비용 없는 거래는 별도 원천 품질 분모로 남긴다.
2. **체결 후 분할 반사실:** 원거래의 최초 fill 직후부터 후보 leg의 고정된 TTL/청산 전까지, 판정 시점에 알 수 있던 유형과 기준 가격으로 1/2/3 leg 및 허용된 0/0.3/0.8% 또는 호가 오프셋을 재생한다. 원체결보다 낮은 가격을 나중에 실제 시장이 방문했는지 조사한다. 지정가보다 낮은 가격에서 관측된 후속 거래로 조건부 fill 시나리오를 만들되 실제 대기열·수량이 미확인된 한 실체결로 단정하지 않는다. 동일 가격 터치만 관측된 거래는 도달률과 fill 불확실성을 별도로 보고한다. **가격 미도달·검증된 무체결도 원거래 분모에 남겨** 후보의 놓친 기회로 계산한다. probe-first 1주와 조건부 잔량, 미체결·부분체결·취소·재주문, 같은 현금·수량 상한을 재현한다. 관측된 원수량을 넘는 후보분은 depth 근거가 없으면 보수적 수량 시나리오와 `quantity_expansion_unproven`으로 분리한다. 후보 fill이 원거래 청산보다 늦으면 불가로 처리한다.
3. **짝비교 경제성:** 최초 선정은 각 거래의 실제 진입·실제 종료·실제 비용 후 PnL을 기준으로, 원래 청산 시각/가격/owner 영수증을 고정한 **조건부 반사실**을 계산한다. 후보 체결분의 새 진입원가와 비용, 검증된 무체결의 원거래 대비 놓친 이익/손실, 부분체결 잔량·자본 점유를 반영한다. 이 방식은 체결 시각/가격이 달라졌을 때 청산 판단도 달라질 수 있다는 한계를 `fixed_exit_assumption`과 보수적 비용/청산 민감도로 표시한다. 청산 영수증·비용이 없으면 EV를 null로 두고, fill 불확실성은 보수/중립/상방 추정 EV 범위로 드러낸다. 향후 갱신에서는 원래 종료 owner의 경로 재생과 실제 적용 주문 영수증을 추가로 요구한다. 동일 거래에서 기존 실제 실행과 후보의 **추정** 순EV/순이익, fill 참여율·손실 꼬리·가장 나쁜 날짜를 유형×분할별로 비교한다. 결과를 실제 대안 체결/실현 PnL이라고 부르지 않는다.
4. **최초 정책 생성 — 낮은 허들:** 전체 완료 거래 원모수와 유효 source/비용·실제 fill·체결 후 가격 경로, 동일 거래의 조건부 쌍비교, 수량 보존·25%/95%/브로커 상한 및 P1 가격 소유권이 필수다. **기존 4조합 영수증 30건, join 80%, 완전한 주문 대기열 영수증, 독립 최신일 holdout, 적용 후 자연 성과, 고정 +0.10% EV 바닥은 최초 발행 요건이 아니다.** 확보된 `paired_net_comparable`이 1건 이상인 지원 유형은 부모와 후보 중 보수적 비용 후 추정 EV가 높은 허용 조합을 초기 선택할 수 있다. 표본·coverage·미체결 비용·불확실성은 그대로 공개하고, 증거가 없거나 개선이 불명확한 leaf는 현 부모 수량·분할을 명시적으로 선택한다. 전체 유형을 포함한 하나의 초기 정책 artifact는 생성하되 증거 부족 leaf를 최적화 완료로 표시하지 않는다. 처음 선택한 수량 증가/분할 변경은 별도 canary·rollback/중단 규칙으로만 활성화한다.
5. **후속 정책 갱신 — 강화 허들:** 최초 정책을 부모로 고정하고 이후 **새로운 독립 거래일**의 적용/비적용 원천과 원모수 전체를 새로 평가한다. 같은 거래의 challenger-parent 비용 후 순EV/순이익·fill 참여율/미체결 기회비용·나쁜 날짜, 유형별 재생 coverage와 결손·검열, 최근 holdout, 실제 PID 정책 소비와 적용 후 주문/terminal을 함께 요구한다. 최소 완료 거래/날짜/coverage 기준은 최초 데이터 census의 유형별 실현 가능 표본수를 보고 사전에 버전 고정하고, 부족하면 마지막 정책을 carry한다. 기존 30건/80% 4조합 계약은 구 `entry_execution_sizing_policy`의 challenger 경로에만 남긴다. 새 완료 거래 기반 v2 갱신 validator는 **초기 validator와 별도**로 구현하고, 4조합 원본 plan 영수증 0건을 유일한 갱신 불가 사유로 만들지 않는다.
6. **단일 발행·적용 계약:** 초기/갱신 모두 유형 classifier, 수량 tier, 선택된 분할 템플릿/가격 오프셋, P1 가격 정책 참조를 동일 세대의 불변 `entry_execution_sizing_policy`로 결속한다. `generation_kind=initial_completed_trade_seed|refresh`, 사용한 전체 원모수·유효 쌍비교·검열·유형별 선정 사유, `source_date` 범위, `effective_from`, 정책/원천/보고서/terminal SHA, 부모/CAS, rollback, `runtime_apply_allowed`를 보존한다. 4조합 영수증은 있으면 별도 교차검증으로 붙인다. 동일 부모 중복 실행은 동일 artifact를 내고 다른 자식 동시 발행은 CAS로 막는다. 보고서→terminal→strict handoff/summary→PREOPEN→PID가 같은 세대를 소비해야 한다.

**연결 위치:** 최초 수량 receipt는 `sniper_state_handlers.py`/`position_sizing_allocator.py`, 완료 실거래 census·체결 후 경로·유형×분할 반사실/선정과 구 4조합 진단은 기존 `entry_split_order_plan.py`/`strategy_owner_replay.py`의 같은 family 소유 아래 둔다. 장후 호출·완료 표시는 `run_threshold_cycle_postclose.sh`와 `src/engine/automation/postclose_summary_handoff.py`에 연결한다. 발행 세대는 `src/engine/automation/runtime_policy_bootstrap.py`와 `run_threshold_cycle_preopen.sh`가 불변 파일 SHA로 전달하고, `runtime_apply_gap_audit.py`가 실제 적용 간극을 대사한다. 선택 릴리스/PID 영수증의 원천 경로와 파일 SHA가 다르면 PREOPEN 성공으로 표시하지 않는다. 별도 수량 daemon·중복 DB·generic Daily 튜너는 만들지 않는다.

## 5. 날짜 제한 제거와 첫 기본정책 적용

1. **v2 결합 정책 로더:** `ACTIVE_DATE == today`와 파일명 날짜 검색을 수량/결합 정책의 지속 경로에서 제거하고 `effective_from <= decision_time` 및 명시적 교체/롤백 세대로 판단한다. 미래 효력일 정책은 사용하지 않는다. 완료 거래 원천일 범위는 출처 증명으로 계속 검사하며 실행일로 재기록하지 않는다. 파일 내용 SHA, schema/version, `generation_kind=initial_completed_trade_seed|refresh`별 서로 다른 evidence validator, 부모 연속성, allowlist, 선정 권한, operator lock과 hard safety는 유지한다. 공용 `_runtime_policy`를 일괄 변경하면 가격/scale-in 정책도 바뀌므로 수량·결합 로더만 별도 지속 계약으로 이행한다.
2. **첫 시작/재시작:** 코드 내 5단계 기본값 대신 검증된 `current` 포인터가 가리키는 **완료 거래 기반 최초 v2 정책**을 읽는다. PREOPEN은 당일 release/bootstrap/PID를 여전히 검증하지만 그 안에 수량 tier·분할 템플릿·P1 정책 참조의 같은 결합 SHA를 결속한다. 주말·월경·재시작에도 동일 정책을 유지하고, 새 정책은 다음 검증된 효력 시점에만 교체한다. 장중 임의 파일 교체나 env 값만으로 승격하지 않는다.
3. **실패 경로:** 포인터·바이트 SHA·부모·적용 권한이 깨지면 선택 릴리스와 함께 봉인한 마지막 검증된 불변 부모를 다시 검증해 사용하고 명시적 결손 영수증을 낸다. 현재 운영 잠금이나 안전 계약과 충돌하는 부모는 재사용하지 않는다. 부모도 검증 불가하면 flat 10% 보수 경로로 제한하며 기존 상한/주문 가드는 계속 적용한다. 이미 열린 포지션의 AVG_DOWN은 진입 때 고정한 공식·tier/hash를 쓰므로 새 `current`가 소급 변경하지 않는다. 구 v1의 날짜 제한 정책은 불변 감사물로 읽되 v2 `current`에 자동 편입하지 않는다.
4. **검증 시나리오:** 효력 전·당일·다음 거래일·주말·월경·재기동, 부모 충돌/원자 교체, 수량 파일만 교체된 경우, 결합 정책의 참조 SHA 불일치, 오래된 PREOPEN/PID env, NXT/UNKNOWN/원천 결손, 원진입 hash 유실을 시험한다. 기존 일자별 가격/분할/운영 override의 유효기간은 바꾸지 않는다.

## 7. 구현 순서와 완료 판정

1. 현 호출 그래프·퇴역 후보 도달성·9/23의 원본 4조합 0건과 완료 실거래 census를 짧은 증거표로 고정한다. 2026-06-05 이후 모든 완료 거래의 원진입 fill→owner/청산/비용·체결 후 가격 경로 결합률과 결손 사유를 먼저 산출한다.
2. 런타임 순수 feature/유형 classifier와 수량 결정 receipt를 추가하고 기존 5단계 동작 동등성을 검사한다. 그다음 장후 동일 classifier와 완료 거래 전수, 체결 후 저가/체결 가능성·후보 청산/비용, 유형×수량×분할 쌍비교를 연결한다. 기존 4조합은 별도 교차진단으로 남긴다.
3. **초기 생성** 전용 평가/validator로 전체 완료 거래의 유효 후보와 부모 fallback을 한 정책에 발행한다. **갱신** 전용 평가/validator는 새 독립 날짜·적용 후 자연 결과를 요구한다. v2 발행기/current CAS/지속 로더 및 bootstrap/PID hash 결속을 구현하고, Plan Rebase §5의 기존 결합 challenger 근거 계약을 이 두 경로로 명시적으로 이행한 뒤 최초 정책의 데이터 replay·성능 검증을 마치고 기본값으로 전환한다. 가격 leg는 P1 소유자가 승인한 판정 전 기준·허용 오프셋으로만 생성하고, split allocator가 독립 숫자 가격 소유자가 되지 않도록 소비 계약을 검증한다.
4. 위 전환 후 도달성 0으로 확인된 구 수량 환경변수·date guard·중복 계산·퇴역 수량 후보 코드를 제거한다. 각 단계는 구현→self review→보완→재검토→영향 pytest/compile·wrapper `bash -n`/계약 테스트·`git diff --check`로 닫는다. 문서/체크리스트 수정 시 link/owner/authority 검사와 print-only parser를 수행한다.
5. 실제 구현 시점의 Plan Rebase §5 소유 계약 및 **그 날짜의** 체크리스트 OPEN 항목을 일치시키고, 별도 승인·롤백 경계에 따라 불변 릴리스/PREOPEN/PID를 검증한다. 이 계획 문서만으로 배포·재기동·수량 변경·주문을 실행하지 않는다.

AVG_DOWN/PYRAMID의 원진입 공식 pin, 25% 최대, 95% 예산, 브로커·종목·단계·현금 상한과 주문 안전 가드는 유지한다. 결합 수량×분할 정책 로더의 `ACTIVE_DATE==today` 만료 조건도 제거하고 원본 `active_date`를 효력 하한으로만 읽는다.
- 장전 bootstrap은 현재 선택 파일, 원본 stage, 불변 정책을 매번 검증해 수량 정책 파일·SHA를 env/manifest의 `initial_quantity_current_verified` 소유자로 결속한다. operator 값·lock이 같은 키를 덮으려 하면 중단한다. manifest에는 current 파일 SHA, 내용 hash, 정책 파일 SHA와 원천일/효력일을 기록하고 verifier가 재대조한다. 실제 선택 release와 PID 환경 소비, 첫 자연 수량 결정은 별도 영수증이다.
- 초기 기본정책의 모든 유형은 기존 주문 형상과 기존 프로필 시간을 **그대로** 사용하므로 새로운 `T/n` 실주문 dispatcher가 이 첫 배포의 실행 경로가 되지 않는다. 새 분할·최적 총시간을 선택하는 후속 정책은 앞 절의 순차 leg·probe 포함·취소 및 broker 최종 확인·재시작 복구 계약을 구현하고 검증한 뒤에만 활성화한다. 최초 정책의 배포 가능성과 후속 주문 로직 변경의 우월성/실증을 혼합하지 않는다.
