# 스캘핑 트레일링 익절 4축·3시장 장후 튜닝 구현계획

작성: 2026-09-25 KST. 상태: **작업본 구현·검증, 자연 원천/정책 선택 미완료**. 이 문서는 임계치 후보 생성과 과거 증거 수용 방법을 제안한다. 임계치 변경, 정책 발행, 봇 재시작, 실주문은 이 문서 작성으로 실행되지 않는다.

## 1. 범위와 현재 기준

- 대상은 메인 실거래 `SCALPING/SCALP`의 단일 일반 익절 owner `scalp_trailing_take_profit`이다. `trailing_peak_worsen_floor`는 동일 판정의 발동 유형이다. hard/protect/emergency·손절, 주문·수량·provider 및 다른 custody의 권한은 별도다.
- 정책 시장은 `PREMARKET`, `REGULAR`, `INTEGRATED_AFTERMARKET` 세 개로 고정한다. **네 임계치 모두 시장별 값**을 갖도록 설계한다. 기준 벡터는 각 시장에 `(시작 0.6%, 강점수 75, 약폭 0.4%, 강폭 0.8%)`이다. 유효 시장은 평가 시각의 공통 `session_contract`로 정하며, 포지션이 시장 경계를 넘을 때 arm 상태와 peak ledger를 유지하고 그 평가 시각의 시장값을 적용한다. 매매 불가·시장 미식별 시각을 임의로 셋 중 하나에 넣지 않는다.
- 현재 `trailing_start_replay.py`는 시작값 하나의 보고 전용 계산을 구현했다. `0.3~1.2%` 격자, 학습 30건·5일/검증 10건·2일, 최우선 매수호가 전량 체결 모형, 연구 후보 선정식은 **구현상의 임시 선택**이다. 이를 합의된 4축 튜닝 정책이나 자연 실거래 성과로 해석하지 않는다. 이 계획의 구현에서는 해당 값을 버전이 붙은 연구 설정으로 분리하고, 아래 공통 판정·후보 계약에 맞춰 시작값 계산도 다시 검토한다.
- 현재 시작값 집계는 `len(common)==len(by_id)`와 `not source_gaps`를 요구하여, 한 포지션의 식별 가능한 결손도 시장 전체 후보를 막는다. 과거 적격 부분집합을 쓰려면 이를 **ID별 제외·공통 지원 분모**로 바꾸고, 전체 차단은 완료 census/원천 계약 자체가 없거나 결손 ID를 격리할 수 없을 때로 한정해야 한다. 이것은 시작값 축에도 필요한 구현 보완이다.
- 정책 키는 `KORSTOCKSCAN_SCALP_TRAILING_{START_PCT|STRONG_AI_SCORE|LIMIT_WEAK|LIMIT_STRONG}_{PREMARKET|REGULAR|INTEGRATED_AFTERMARKET}` 형식의 12개 유효값과 단일 시장 벡터 hash로 확장한다. 현재 scalar 네 값은 세 시장의 현행 fallback이며, 시장별 키가 도입되어도 fast/normal에 서로 다른 값이 보이면 안 된다. 평가 시각의 시장·효력 날짜·값 hash를 직접 신호까지 연결한다.
- 9/25 조사 시점 선택 릴리스는 `39eee6ac8eaf7c3155a7cc9746da9bc2c0bd0dda`다. 이 작업본의 시장별 4축 코드나 새 bootstrap v3을 실제 PID가 소비한다는 영수증은 없다. 기존 9/28 bootstrap의 `verify=pass`는 그 작성 시점의 확인이다. 9/23 관측 파일은 구 schema로, clean-baseline 완료 329건 중 정확 비용 연결 6건, 직접 `exit_signal` 0건, 전체 EV `null`이다. 기존 205건 분봉 연구는 규칙 추정·대부분 부정확한 청산 초 시각·호가/잔량 부재 때문에 가격 경로 진단으로만 사용한다.
- 공통 기초 모집단은 [완료 포지션 계획](./scalp-trailing-completed-position-cohort-plan-2026-09-24.md)의 `strict_completed_position_ids`다. 실제 BUY 체결 수량, 전 SELL 체결과 최종 잔량 0, DB `COMPLETED`·유효 수익률, 체결 기반 비용 증거는 **과거 자료를 사용할 때도 완화하지 않는다**. 다른 규칙의 청산은 경쟁 청산으로 같은 전체 완료 분모에 포함하고, 열린 포지션은 별도 검열한다. clean baseline `2026-06-05T00:00:00+09:00` 이전 자료는 후보·적용 근거에서 제외한다.

| 축 | 런타임에서 바꾸는 것 | 후보 재생에 필요한 시점별 원천 | 결손 시 처리 |
| --- | --- | --- | --- |
| `SCALP_TRAILING_STRONG_AI_SCORE` | **유효** 보유 AI 점수가 경계 이상일 때 강폭을 선택한다. 점수 결손·TTL 만료·provider 불명은 현행의 약폭 fallback을 유지한다. | 모든 관련 평가의 원점수, 생성·수신·평가 시각, provider, 역할 gate, 품질/TTL, 사용 여부, 정책 세대, peak와 bid. 후보 점수 경계로 강약을 매 평가마다 재분류한다. | 최종 SELL 시점 점수를 이전 평가에 대입하지 않는다. 유효 점수 경로가 없으면 이 축의 후보 비교는 `source_gap_score_path`; 강약이 어떤 경계에서도 같음이 증명된 구간만 0효과로 둘 수 있다. |
| `SCALP_TRAILING_LIMIT_WEAK` | arm 이후 약한 점수 또는 fallback에서 peak 대비 실행가능 bid의 되돌림폭을 바꾼다. | position 시작부터 경쟁 청산까지 순서가 있는 peak·평가 시각·시장·신선한 bid/잔량·약/강 상태와 최초 후보 crossing; 후보가 더 늦게 팔면 실제 청산 **후**에도 첫 crossing 또는 우선 안전 청산까지의 경로. | 분봉 고가만으로 초 단위 첫 crossing·실행가능 매도가를 만들지 않는다. 첫 crossing 미식별 구간은 후보별 검열 또는 손익 구간으로 남긴다. |

공통 순수 판정은 현재 `evaluate_trailing_take_profit`을 재사용한다. 후보별 `arm_latched`, peak, 시장, 강약, 첫 trigger를 독립 상태로 재생한다. fast/normal의 가격 원천·평가 순서와 stop/보호/경쟁 SELL의 우선순위를 실제 런타임과 맞춘다. 후보가 실제보다 먼저 청산하면 해당 시각의 bid·잔량·수량·세금/수수료·슬리피지 범위로 **모델 손익**을 만든다. 실제와 같은 시각·규칙이면 관측 체결 손익을 사용한다. 후보가 늦으면 실제 청산 이후 경로와 경쟁 규칙을 재구성할 수 있을 때만 모델 손익을 만든다. 그 외는 `censored_after_actual_exit`이며 0효과나 실제 손익으로 채우지 않는다. 모델 매도는 실제 체결 주장과 분리한다.

## 3. 단일축과 복합축을 평가하는 순서

**권장 설계는 단일축 민감도 분석 후 제한된 4축 복합 비교**다. 시작값은 arm 시점을 바꾸고 두 폭은 trigger 시점을 바꾼다. 점수 경계는 약폭과 강폭 중 어느 것을 사용할지 결정하므로 점수 경계를 단독으로 최적화하면 두 폭의 현재값에 결과가 종속된다. 단일축만으로 최종 정책을 고르면 이 상호작용을 놓친다. 반대로 처음부터 전체 격자를 무제한 탐색하면 연산량과 다중 비교 편향이 커진다. 후보 수와 탐색 순서는 학습 구간만 보고 봉인하고, 최신 검증 구간에서는 후보를 다시 고르지 않는다.

1. **동일 분모의 단일축 진단:** 각 시장에서 나머지 세 값을 현행으로 고정하고 시작·점수·약폭·강폭의 후보별 첫 신호, 포지션별 비용 후 `paired_delta_pnl_krw`, notional weighted EV, 순이익, 손실 악화와 후보별 적격/검열 ID를 산출한다. 세 시장 설정을 한꺼번에 바꾸지 않고 해당 시장값 하나의 변화가 시장 경계를 넘는 포지션에 미치는 영향까지 전체 포지션 경로로 재생한다. 시작값의 기존 격자는 후보 제안일 뿐이며, 점수/폭 격자와 허용 범위·표본 기준은 학습 구간의 관측 해상도와 안전 범위를 확인한 뒤 **평가 실행 전에 버전·hash로 봉인**한다. 현행값은 항상 포함한다.
2. **상호작용 측정:** `시작×약폭`, `시작×강폭`, `점수×약폭`, `점수×강폭`, `약폭×강폭`을 같은 적격 ID에서 비교한다. 각각의 결합 효과에서 두 단일 효과의 합을 뺀 상호작용과 `시작값−활성 폭`, 첫 신호 실행가능 순수익, 미실현 후속 상승, 악화된 큰 손실을 함께 공개한다. 점수가 항상 fallback이면 점수 관련 조합을 식별 불가로 표시한다.
3. **제한된 4축 후보:** 학습에서 선정한 현행값과 각 축의 소수 후보로 4축 정책 벡터를 구성한다. 현행·단일축·상호작용 후보를 모두 포함한 사전 봉인 후보집합만 최신 독립 구간에서 평가한다. 상호작용 이득이 반복되지 않으면 단일축 변경을 우선한다. 복합 변경은 개별 변경보다 추가로 개선되고 손실·source-quality 조건도 충족할 때에만 후보로 낸다. 시장별 후보가 서로 다른 포지션에만 작용한다는 가정을 하지 않고 **최종 3시장 정책 벡터**를 전체 포지션에서 한 번 더 재생한다.
4. **선택 통계:** 실제 incumbent 비용 후 손익과 후보 모델 비용 후 손익의 동일 ID 차이를 주 지표로 한다. 학습·최신 날짜 holdout, 일자 묶음 재표집의 불확실성, 다수 후보 검색을 고려한 동시 비교, 하위 손실·주문 실패·호가 부족을 함께 보고한다. 단순 익절 승률, 청산 후 최고가, 평균 수익률만으로 값을 고르지 않는다. 기존 시작값 코드의 30/10건·5/2일, 단일 호가 전량 체결, 단순 최고 train EV 선택은 이 계약을 검토하면서 재확정하거나 수정한다. 이 계획은 새 수치 허들을 임의로 승인하지 않는다.

구현 논의용 **초기 격자안**은 시작 `0.3~1.2%/0.1%p`, 유효 점수의 학습 구간 10~90백분위 안에서 5점 간격과 현행 75점, 약폭 `0.2~0.8%/0.1%p`, 강폭 `0.4~1.2%/0.1%p`다. 강폭이 약폭보다 좁아지는 조합은 별도 가설·안전 검토가 없으면 제외한다. 학습에서 **단일축 성적과 두 축의 상호작용 후보를 합친 집합**으로 축당 현행값·최대 두 후보를 고른 다음 제한된 4축 조합을 시장당 최대 `3^4=81`개 재생한다. 단일축 효과는 작아도 결합 효과가 큰 값을 누락하지 않기 위한 절차다. 세 시장의 최종 정책 조합은 시장당 현행값·최대 두 후보를 조합한 최대 `3^3=27`개를 전체 포지션 경로에서 재검증한다. 이 수치와 후보 공간은 **사용자 검토용 제안**이며, 데이터 가용성 조사 후 score 분포·가격 tick 해상도·계산량을 확인하여 실제 실행 전에 확정한다. 검증 구간 결과를 보고 격자를 늘리거나 바꾸지 않는다.

기존 [9/24 원천 연결·정리 계획](./scalp-trailing-postclose-threshold-lineage-and-pruning-plan-2026-09-24.md)의 “한 번에 한 축”은 그 당시의 후보 변경 범위였다. 이 계획은 사용자가 요청한 복합축 효과 검토를 추가한다. 복합축의 후보 산출과 실제 적용은 위 상호작용·경제성·안전 검사를 통과한 **하나의 3시장 정책 버전**으로 취급하여 같은 stage에 복수 canary를 만들지 않는다.

## 4. 자연 신규 표본 없이 과거 자료로 현행값을 바꾸는 경로

**신규 자연 산출물이 없다는 사실만으로 후보 생성을 금지하지 않는다.** clean-baseline 이후 과거 포지션마다 필요한 필드를 축·후보·발동 시각에 맞춰 다시 판정한다. 과거 분석 보고서의 추정 라벨을 직접 신호로 승격하거나, 불완전한 행의 null을 0으로 치환하지 않는다.

| 증거 등급 | 포함 조건 | 허용 결과 |
| --- | --- | --- |
| `historical_direct` | 엄격 완료 모수, 당시 정책/런타임 세대, 직접 신호 또는 동일 결과를 재현하는 원시 판정 경로, 시각순 AI/호가/잔량, 후보 first crossing, 비용이 결합됨 | 자연 신규 자료와 같은 방식의 모델 paired 비교. 실제 incumbent 손익과 모델 후보 손익을 명확히 분리 |
| `historical_reconstructed` | 엄격 완료 모수를 유지하고 누락된 **비필수** 필드를 원시 로그·보존 tick/호가·기존 API 응답으로 재구성하며, 시각·종목·route·정책 hash와 검증 영수증을 남김. 후보가 실제보다 앞서 청산하면 이후 1/3/5/10분 창은 필수가 아님. 늦은 후보는 실제 청산 후 실행가능 bid 경로와 안전/경쟁 청산 경로가 있어야 함 | 재구성 범위에서만 후보 비교. 시각·체결·slippage 불확실성을 상·하한으로 내고 **보수적 하한에서도 개선되는** 후보만 값 변경 심사에 올림 |
| `historical_diagnostic` | 분봉 OHLC/최고가, 추정 청산 규칙, 청산 시점 단일 AI 점수, DB 가격 또는 비용 모형만 있음 | 후보 범위·원천 수집 우선순위 진단. 현행값 변경 근거 불가 |

- 제외해도 되는 필드는 **그 후보의 인과 계산에 사용되지 않는 필드**다. 예를 들어 앞당겨 청산하는 후보에는 실제 청산 뒤 장기 가격창이 필요하지 않고, 점수 경계를 바꿔도 모든 평가에서 강/약이 같음이 증명되면 그 구간은 0효과다. 정확한 최종 SELL 시각은 공통 완료 모수에서 필수가 아니지만, 후보 신호와 실제 종료의 선후를 정할 수 없으면 그 후보 비교에서는 제외한다.
- 제외할 수 없는 필드는 실제 BUY/SELL 수량 보존·`COMPLETED`·유효 수익률·체결 기반 비용 증거와, 해당 후보의 최초 arm/crossing·당시 강약·실행가능 매도 가격/수량을 식별하는 필드다. 1분봉 고가와 추정 청산 시각은 first crossing의 점 추정치가 아니다. 1분봉의 시각·가격 순서가 모호하면 가능한 결과의 구간을 계산하고, 구간이 정책 우열을 뒤집으면 결론을 보류한다.
- 값 변경 심사는 후보별 **공통 지원 ID**, 전체 엄격 완료 census 대비 제외율, 시장·AI 상태·실제 청산 규칙·날짜별 누락 편향을 공개한 뒤 진행한다. 식별 가능한 결손 행은 격리하고, 모집단 자체의 ID/hash 대사가 불가능하면 전체 입력을 막는다. 과거 복원이 가능하더라도 동일 원천으로 후보 격자를 고르고 검증하면 안 된다. 시간순 학습과 손대지 않은 최신 날짜 holdout을 분리한다.
- 결손으로 빠진 포지션이 특정 시장·높은 변동성·큰 손실에 몰렸는지 확인하고, 빠진 ID의 가능한 결과 범위를 넣은 민감도 분석을 함께 낸다. 결손을 제외한 표본에서만 유리하고 전체 모집단의 보수적 범위에서는 우열이 뒤집히면 현행값을 유지한다. 과거의 직접/복원 등급을 섞어 평균 하나만 보고하지 않는다.
- 현행값 변경의 실제 경로는 `historical_direct|historical_reconstructed`의 적격 paired 결과 → 시장별/최종 3시장 후보와 불확실성·tail·안전 검토 → 버전 고정 정책 선택 → 다음 PREOPEN bootstrap의 네 값×세 시장·hash·rollback 대사 → 선택 릴리스 → 실제 PID 소비 → 적용 후 자연 체결 비용 후 평가다. **새 자연 표본을 후보 선정의 선행 필수 조건으로 두지 않는다.** 반면 과거 자료가 `historical_diagnostic`에만 머물면 값은 유지하고 부족한 producer를 명시한다. `historical_reconstructed` 결과는 실제 후보 체결 증명이 아니므로 초기 적용 범위와 즉시 rollback 감시는 기존 canary·hard-safety 계약으로 제한한다.

## 6. 필수 실행 성능 검증

구현 완료 조건에 **실제 계산 성능 검사**를 포함한다. 기존 시작값의 합성 계측 영수증은 329포지션×256전이 재생 9.208초, 집계 0.314초, 최대 RSS 53.1MB다. 이는 I/O가 없는 합성 입력이므로 새 전체 stage 소요시간의 예측값으로 사용하지 않는다.

1. 후보 격자와 적격/제외 분모·원천 hash를 고정한 뒤, 단순 참조 재생과 전처리/캐시 적용 재생의 **모든 후보별 first crossing·검열·손익·ID 해시가 일치**하는지 비교한다. 속도를 위해 시장·날짜·후보·비용 범위나 결손 ID를 줄일 수 없다.
2. 동일 머신에서 329×256, 1,000×40, 보존된 최대 실제 원천일을 각각 cold/warm 입력으로 계측한다. `wall_sec`, user/system CPU, 최대 RSS, swap, 읽기/압축 해제 I/O, 후보 수, 평가 전이 수, 적격·제외·검열 수, exit status를 기록한다. 시작값 단독과 4축 단일/결합 계산을 같은 입력에서 구분한다.
3. 실제 postclose 경로의 `trade_review → post_sell_feedback → holding_exit_observation → sentinel/summary`에 대해 단계별·전체 소요시간과 strict handoff 시각을 기록한다. 기존 stage timeout 및 그날 다른 작업을 포함한 종료 시간창 안에 끝나고 swap이 발생하지 않아야 성능 수용이다. 초과하면 공통 feature/first crossing 캐시, candidate vector화, bounded source read를 우선 고친다. 계산량을 줄이기 위해 품질이 좋은 행이나 검증 후보를 사후 삭제하지 않는다.
   - T0에서 같은 머신·동일 입력의 기존 stage wall/CPU/RSS와 wrapper timeout, 장후 다음 단계 시작까지의 여유시간을 먼저 기록하고 **성능 예산을 코드 구현 전에 봉인**한다. 실측 성능 판정은 `완료 wall < 봉인된 가용 시간`, `swap=0`, `exit_code=0`, `검증 후보·공통 ID·원천 hash 동일`을 모두 요구한다. 예산이나 원천 규모를 기록하지 않은 실행은 성능 PASS가 아니다.
4. 코드 리뷰·의미 동등성·성능 검사 통과 전에는 비싼 전체 장후 재생, release 선택, 정책 발행을 진행하지 않는다. 성능 PASS는 후보의 경제성, 실제 PID 소비 또는 적용 후 수익 증명이 아니다.

## 7. 실값 적용 전 합의할 정책 선택

이 계획은 아래 선택을 **제안 상태**로 남긴다. 사용자가 값을 정하면 격자·비용·검증 계약을 버전으로 봉인하고 구현한다.

1. 시장별 네 축의 후보 범위·간격과 시장 간 값 공유 여부. 세 시장 분류 자체는 고정이다.
2. 역사적 복원 자료에서 허용할 후보 매도 모형: 최우선 bid의 관측 수량 전량 충족, 부분 수량·슬리피지 상한, 주문 실패 시나리오 및 보수적 손익 하한.
3. 단일축 변경과 복합축 변경의 선택 조건, 최소 독립 날짜/표본, 다중 비교·tail 허들. 기존 시작값 코드의 30/10건·5/2일과 단순 최고 train EV는 재검토 대상이다.
4. `historical_reconstructed`만으로 적격해진 후보를 어떤 범위의 첫 정책/canary로 적용할지, 이후 자연 실체결 비용 후 결과로 유지·복귀할 판단 시점.

참고 방법론: 순차 정책의 과거 평가에는 후보 행동이 관측 경로에서 식별되는 지원 범위가 필요하고, 많은 후보 중 최고 성적을 고르는 과정에는 선택 편향이 생긴다. [과거 정책 평가 연구](https://arxiv.org/abs/2110.12343), [다중 비교·백테스트 과적합 연구](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551). 이 논문들은 본 시스템의 후보값이나 적용 권한을 정하지 않는다.

## 8. 9/25 구현 결과와 남은 수용 경계

- 네 축의 시장별 runtime/bootstrap, source-bound 단일·쌍·제한 복합 재생, 시작값 ID별 결손 격리, 보고서의 연구 후보와 명시적 정책 선택 영수증 연결을 작업본에 구현했다. 초기 격자는 이 문서 §3의 연구 설정으로 남고, 동일 날짜 holdout을 보고 재설정하지 않는다. 정책 선택에는 별도 `selection_review`의 원천·실행모형·동일 stage·rollback 검토가 필요하다.
- [과거 원천 조사](../audit-reports/2026-09-25-scalp-trailing-four-axis-historical-source-availability.md)는 보존된 329건을 현재 엄격 완료 모수로 인정하지 않는다. 직접/복원 적격 경로 0건이므로 현재 네 값의 자연 최적값이나 변경 승인은 산출되지 않았다.
- [구현 리뷰·성능 기록](../audit-reports/2026-09-25-scalp-trailing-four-axis-implementation-review-and-performance.md)에 회귀 수정, 합성 329×256·1000×40과 보존일 stage 실측, 미측정 strict handoff 경계를 기록했다. 현재 공통 세션 계약은 프리마켓 청산을 허용하지 않아 프리마켓 익절 값은 식별 불가다. 릴리스·PID 적용이나 실주문은 이 작업에 포함되지 않는다.

## 9. 후속 지시: 과거 완료 표시의 중립 추정 재생

사용자의 후속 요청에 따라 [중립 추정 시뮬레이션·리뷰](../audit-reports/2026-09-25-scalp-trailing-legacy-neutral-scenario-review.md)를 엄격 4축 재생과 **별도 진단 층**으로 추가했다. 329건 중 가격·수량·매도시각이 식별된 312건에 보고 MFE 또는 추정 익절 규칙의 조건부 최고점을 사용하며, 남은 최고점·AI 경로·후행 실행가격의 미식별 변화량은 중립 시나리오로 남긴다. 추정 약·강과 슬리피지 범위를 함께 표시한다. 보고 수익률과 설정 비용으로 계산한 시나리오 변화는 `COMPLETED` 실제 체결 비용 후 paired EV가 아니며 bootstrap·선택 정책의 입력이 아니다. 장후 누적 census의 주말 누락 판정과 완료일 기준 검증 분할도 함께 보완했다.
