# Main 기계판정 미진입 상승 회복 우선순위: 2026-10-02 장후 적용 계획

## 결정과 적용 경계

- 2026-10-02 장중에는 이미 선정된 기계 정책, 날짜별 번들, 로더와 PID의 판정 경로를 유지한다. 새 후보 탐색·승계 코드는 장중 프로세스에 적용하지 않는다.
- 새 계산 로직의 첫 실행 대상은 **2026-10-02 원천을 포함하는 그날 장후 작업**이다. 코드 리뷰, 회귀·성능 시험, 불변 릴리스 선택을 장후 시작 전 끝내고, 장후 생산자만 새 버전을 소비하는지 확인한다. 통과한 새 정책의 적용일은 계산일이 아니라 다음 실제 거래일로 산출한다. 조건이 부족하면 기존 정책을 승계한다.
- 범위는 Main 기계판정의 `KRX|KRX_REGULAR` 정확 범위다. 보조 AI, 주문·가격·수량·제공자·안전 차단, 다른 세션의 정책 권한은 변경하지 않는다. 2026-09-29 이후의 적격 원천만 누적한다. 6~8월 자료와 9월 28일까지의 자료는 후보 학습·순위·승계에 쓰지 않는다.

## 확인된 결함과 기준점

2026-09-30 평가 보고서의 KRX 정규장에는 적격 시도 2,409건(9/29 학습 1,828건, 9/30 후행 검증 581건)이 있었다. 학습에서 기존 `BLOCK/RECHECK`의 비용 결속된 상승 경로 성공을 되찾은 후보가 5개 있었지만, 현행 전체 선택 집합의 보정 승률 순위가 91개 후보 중 `e7edb9d0a446`을 택했다. 이 후보는 미진입 회복 없이 기존 `ENTER_NOW` 7건만 막았다. 검증에서는 변경 기회가 1건뿐이고 기존 성공 진입 1건을 잃어 승계가 거절됐다. 따라서 “회복 후보가 없었다”가 아니라 **회복 후보가 최종 선택 전에 밀렸다**가 정확한 진단이다. 이 수치는 비용 결속 반사실 경로이며 실제 주문 수익이 아니다.

저장된 91개 학습 점수에 회복 우선 순위를 메모리에서만 적용한 작은 시험에서는 `6908b959dbda`가 첫 후보로 바뀌었다. 학습 시 고유 미진입 기회 2건의 목표 우선 성공을 회복하고 실패 회복은 0건, 기존 성공 진입 76건은 모두 유지했다. 회복 표본의 보정 승률은 42.50%, 전체 선택 집합의 보정 승률은 76.66%(기존 정책 76.17%)였다. 평균 비용 결속 경로 값은 −0.07714%, 기존 정책은 −0.08103%였다. **2건은 승계 근거가 아니며**, 이 후보의 독립 검증 성과는 저장된 점수만으로 알 수 없다. 같은 91개 점수의 최고 후보 선정만 1,000회×3회 반복한 단일 프로세스 표본에서 기존 순위 중앙값은 약 200μs/회, 제안 순위는 약 231μs/회였다(약 31μs, 15.5% 증가). 이는 전체 원천 로딩·재생·장후 실행시간을 측정한 값이 아니다.

## 로직 변경 설계

1. **모집단 고정:** 기존과 동일한 정확한 판정 ID, 기회 ID, 부모 정책 해시, venue/session, 사전 판정 특징과 비용·목표/손절 선후가 확정된 경로만 평가한다. 식별 가능한 결손 행·구간은 이유별로 격리하고, 검증 불가·검열·비용 누락을 실패 또는 0원으로 만들지 않는다. 시도와 고유 기회를 별도로 기록한다.
2. **후보 생성의 제한된 재배치:** 현재 registry 82개 기준 `control 4 + single 82 + 회복 이웃 6 + 결합·분기 4 = 96` 슬롯이다. single에서 회복한 학습 후보를 고른 뒤 6개 이웃을 탐색하되, 단일 임계값 완화로는 두 동시 blocker를 통과할 수 없는 경우를 위해 결합·분기 4개를 별도로 확보한다. 이 4개는 사전 판정 blocker의 동시 발생과 등록 도메인으로 정하며 회복 single의 존재에 종속시키지 않는다. 이웃 앵커가 없으면 6개를 같은 사전 blocker 기반 결합 탐색으로 넘긴다. 하드 차단 좌표는 제외한다. 중복·무효 슬롯을 따로 기록하고 예산 밖 보충 탐색은 하지 않는다. 학습 점수·앵커·생성 정책·순서·커서를 체크포인트에 봉인해 같은 입력의 재개가 같은 정책을 방문하게 한다. 82라는 수치는 현재 registry 수이며 registry 변경 시 예산·커버리지 계약을 함께 재검증한다.
3. **학습 후보의 1차 자격:** 회복 후보는 고유 미진입 기회에서 비용 결속 목표 우선 성공을 적어도 1건 되찾아야 한다. 되찾은 실패도 같은 분모에 넣는다. 기존 성공 `ENTER_NOW`의 재생·보존을 요구하고, 전체 비교 모집단의 보정 승률이 부모보다 낮아지는 후보는 제외한다. 비평가 가능 기존 진입 변화와 치명적 경로 손실은 종전처럼 제외한다. 이 단계는 탐색 후보 지정일 뿐 발행 허가가 아니다.
4. **학습 순위:** 자격 있는 회복 후보끼리 `(회복 고유 기회의 표본 보정 목표 우선 승률, 성공 회복 기회 수, 전체 선택 집합의 표본 보정 승률, 전체 표본 수, 단순성)` 순서로 비교한다. 순위는 이진 승패와 표본 수만 쓴다. 비용 결속 경로 EV, 원화 PnL, 평균 상승폭은 순위에 넣지 않고 경제성·꼬리 위험의 별도 근거로 남긴다. 회복 자격 후보가 없다면 차단 강화 후보를 보고서에 남기되, 이 회복 우선 단계의 대체 승계로 간주하지 않고 부모를 유지한다.
5. **한 후보 동결 후 검증:** 학습에서 정한 **한** 정책과 부모를 이후 독립 기회 모집단에 재생한다. 후보가 검증에 실패해도 차순위 후보를 같은 검증 자료로 교체하지 않는다. 기존 학습 10개·검증 3개 고유 기회 하한에 더해, 이 계획의 회복 우선 승계는 **검증에서 BLOCK/RECHECK→ENTER_NOW가 된 고유 기회 3개 이상**을 요구한다. 기존 ENTER_NOW 차단 3개로 이 요건을 채우지 못한다. 회복 성공·실패·중립과 전체 보정 승률 부모 이상, 원천·비용·치명 손실 조건을 검사한다. 기존 성공 진입 100% 보존은 이번 초기 회복 후보에 제안하는 추가 제약이며 현행 모든 기계 정책에 이미 있던 조건으로 설명하지 않는다. 원래 성공 진입 표본이 없으면 보존율은 null/해당 없음으로 두되 신규 회복 평가를 막는 가짜 0%를 만들지 않는다. 실패·표본 부족·source gap이면 `incumbent_carry`다. 고정된 3학습일·2검증일 대기를 다시 도입하지 않는다.
6. **계약과 소비자 일치:** 새 선택 버전과 회복 점수 근거를 후보·평가 계약에 넣는다. 학습 선택, 발행기, 날짜별 활성화, 기존 발행물 읽기 검증이 동일한 버전별 순위·보존 조건을 사용하게 한다. 기존 v4/v5/v6 발행물의 읽기 의미는 고정한다. 입력 해시·탐색 버전·체크포인트를 분리해 과거 선택을 새 점수로 조용히 재해석하지 않는다. 부모 CAS, 정확 범위, next-date, 선택 릴리스/PID, 원천 품질 검사는 그대로 둔다.

구현 접점은 `src/engine/scalping/ai_action_outcome_calibration.py`의 `build_main_strategy_refinement` 후보 선택·고유 기회 집계와 `src/engine/scalping/entry_strategy_policy.py`의 `machine_admission_rank`·`promotion_errors`·발행 후보 선택이다. 두 소비자의 순위 계약을 동시에 바꿔 연구에서는 선택되고 발행에서는 거절되는 불일치를 막는다. 장중 판정 분기는 만들지 않는다. 기회 identity·시간순 purge·디스크 projection 공용 순수 함수는 기존 scalping 패키지의 `postclose_entry_validation.py`가 소유한다.

기회 identity는 날짜·종목·venue/session·promotion lineage를 함께 검증한다. promotion ID 결손을 trace ID로 대체해 재시도를 독립 표본으로 늘리지 않는다. exact fallback을 증명할 수 없는 행은 연구 카운트만 남기고 승계 표본에서 제외한다. 현재 시도 가중 100% 보존율과 새 고유 기회 회복률의 분모를 보고서에서 명시하고 서로 바꿔 쓰지 않는다.

홀드아웃 회복에는 고유 기회 3개 이상과 회복 성공 가중치 >0이 모두 필요하다. 결과표는 같은 자료에서 `부모 / 현행 v6 / 새 회복 우선 버전`을 비교해 회복 precision·회복률·기존 성공 유지·전체 선택 승률·꼬리 경로·source coverage를 함께 제시한다. 분모가 0이면 비율은 null이다. 정확히 가격이 오른 종목 수나 아주 작은 양수 경로만 늘어난 것으로 성능 향상을 판정하지 않는다. 비용 경계·관측 horizon·순위 규칙을 먼저 고정하고 기존 비용 스트레스 시나리오 및 종목/시간 블록 감도를 보고한다. 비용 스트레스는 경제적 한계의 별도 근거이며 Main 승인 예외에 없는 EV 크기를 후보 순위에 추가하지 않는다.

## 두 계획의 공통 적용·검증 계약

이 절은 [보조판정 보완 계획](compact-auxiliary-pass-veto-postclose-remediation-plan-2026-10-01.md)에도 적용한다.

- **최신 계약 우선순위:** 사용자 지시 및 Plan Rebase 도입부의 9/29 forward/same-day 예외를 적용한다. Rebase §7의 과거 3학습일·2검증일 문구와 현재 코드 하한의 차이를 구현 회귀에 명시하며 날짜 대기를 되살리지 않는다. 이번 요청은 두 계획과 실행 항목 보완이므로 Rebase 본문은 수정하지 않는다.
- **누적·시간순 검증:** 학습에 사용 가능한 것은 경계 시각까지 실제로 알려진 원천·label뿐이다. 기회가 두 split에 걸치거나 label 관측 구간이 겹치면 기회 단위로 격리한다. 10/2 자료를 새 버전의 첫 forward 검증으로 쓰려면 그 결과를 보기 전에 경계·후보 탐색 규칙을 봉인한다. 사전 열람/튜닝에 사용했다면 해당 결과는 retrospective로 표시한다. 같은 검증일 실패 후 재탐색·임계값 변경은 다음 새 검증 구간을 요구한다. 학습-only 개선은 언제든 계산한다.
- **전체 raw 없이 누적:** 9/29 이후의 적격 날짜별 원천 감사·사전 특징·경로·비용·identity를 보존하는 compact projection manifest를 누적한다. 단순 일별 승률 합계만으로 후보 재생을 대신하지 않는다. 입력/계약 hash가 바뀐 날짜만 재구축하고, 후보 재생은 정확 부모와 호환되는 projection을 제한 메모리로 순회한다. 최근 rolling 창과 누적 학습 범위는 별도 표기한다. 오래된 projection이 새 좌표를 재생하지 못하면 해당 좌표의 결손으로 남기며 임의값이나 예전 정책의 action을 새 부모의 action으로 쓰지 않는다.
- **기계와 보조 정책의 결합:** 부모를 `M0/A0`, 각 후보를 `M1/A1`로 기록한다. `M0/A1`에서 얻은 보조 응답·성능을 `M1/A1`의 근거로 재사용하지 않는다. 기계가 새로 ENTER_NOW로 바꾼 기회에 과거 AI PASS가 있었다고 가정하지 않는다. M1 선정 시 호환성을 확인한 기존 A0를 승계하고, A1은 M1의 정확 입력·부모로 재검증되지 않으면 보류한다. M1의 승인된 기계 승률 평가에 보조 AI 실제 체결 성과를 새 필수 하한으로 추가하지 않는다. 합성 후보의 수익 우위는 네 조합의 같은 opportunity 재생/owner 근거가 있을 때만 주장한다.
- **발행·운영:** 두 생산자가 공유하는 번들을 원자적으로 기록하고 parent CAS·scope 정규화·동일 날짜 중복 실행 lock을 검증한다. 하나가 실패하면 다른 성공 정책을 덮지 않으며, 전체 bundle/코드의 호환 가능한 마지막 세대를 보존한다. 중단·OOM·부분 checkpoint를 성공이나 후보 없음으로 기록하지 않는다. 정책 유지가 계산의 유효한 결론인 경우와 실행 실패를 terminal에서 구분한다. 날짜·입력·코드가 바뀌면 summary→strict verifier→controller→finalization의 해당 세대를 다시 닫는다.
- **일정:** KRX 15:30을 모든 세션 종료로 간주하지 않는다. 보조 원천 기록 수리는 10/2 최초 판정 전에 준비하되 현재 기계/AI 정책 해시와 판정 불변을 검증한다. 장후 계산의 새 릴리스는 실제 운용 세션·예약 stage 경계를 확인해 장후 소비자에 적용한다. 장중 봇이 새 코드를 읽는 공용 경로를 덮거나 재기동하지 않는다. 새 정책 적용일은 캘린더 함수가 반환하는 다음 실제 거래일이며 10/3이나 특정 월요일을 하드코딩하지 않는다.
- **중단·롤백:** 10/2 새 코드의 필수 시험이 실패하면 검증된 기존 장후 계산 경로와 현 정책을 사용한다. 새 후보의 성과 미달은 incumbent carry다. 원천/부모 손상·잘못된 날짜 발행·권한 누출은 새 발행을 차단하고 현재 포지션 custody를 보존한 채 기존 승인 rollback 경로로 처리한다. 보호 기준을 낮춰 완료 표시를 만들지 않는다.

성능 시험은 읽기 전용 임시 산출물이나 메모리 계산으로 먼저 실행하고 현행 `current` 정책을 건드리지 않는다. 코드 리뷰→수정→재검토→관련 pytest/compile→동일 입력 재생→장후 투입 순서로 닫는다. 장후 뒤에는 생산자 완료, 발행 버전·부모·적용일, PREOPEN 준비, 실제 다음 거래일 PID 소비를 각각 별도 영수증으로 확인한다. 실제 체결 손익과 순이익은 이후 자연 성과로만 판정한다.

성능 합격선은 구현 전에 동결한다. 동일 소스·표본·96 슬롯·실행 환경의 구/신 버전을 각 3회 별도 프로세스로 실행해 중앙 wall/CPU가 구 버전의 1.20배 이하, peak RSS가 `구 버전×1.10 + 64MiB` 이하이며 기존 stage 절대 timeout·메모리 가드 이내인지 확인한다. 결과 캐시는 입력/정책/계약 해시로만 재사용하며 전체 상세 arm을 후보 수만큼 상주시키지 않는다. 초과 시 원인을 수정하거나 새 버전 투입을 보류한다. 200~500행 층화 표본 외에 고정된 당일 전체 적격 입력을 한 번씩 재생해 종목/시간/결손에 대한 표본 편향과 확장 비용을 확인한다. 신규 provider 호출은 기계 평가에서 0회다.

각 시험은 명령·commit·source/parent hash·split manifest·seed·고유 기회/제외 수·후보 hash·경제 지표·wall/CPU/RSS·통과/실패 이유를 임시 별도 evidence로 보존한다. 원천 load/정규화, 후보 탐색, holdout, 발행 dry-run 시간을 구분한다. 마이크로벤치마크만으로 새 전체 로직의 성능 향상을 통과 처리하지 않는다. 기존 `test_entry_strategy_policy.py`, `test_ai_action_outcome_calibration.py`, `test_mechanistic_entry_runtime_policy.py`, `test_postclose_summary_handoff.py`에서 영향 계약을 검증한다.
