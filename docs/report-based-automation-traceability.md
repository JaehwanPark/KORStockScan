Sentinel 이상치는 자동 튜닝 명령이 아니라 기존 report source bundle 입력이다. 반복 이상치를 이유로 새 관찰축을 늘리지 않고, 운영장애는 incident playbook, 로그 누락은 instrumentation backlog, 정상 변동은 no-action으로 분리한다.

Clean tuning baseline 이전 raw/report/analytics artifact는 archive/audit evidence로만 보존하며 EV, rolling/MTD/cumulative tuning, live-auto promotion, runtime approval, pattern lab promotion, real execution quality approval 입력으로 사용할 수 없다. 같은 날짜라도 clean reset 이전 `generated_at` 또는 mtime을 가진 tuning report/analytics 산출물은 재생성 대상이며, `data/source_quality/clean_baseline_policy.json`이 정책 source of truth다. Baseline 이후 `observation_source_quality_audit` preflight가 contract gap을 찾으면 기본 처리 단위는 target date 전체가 아니라 결손 row/window다. `raw_row_exclusion` manifest와 원본 backup을 남기고 결손 row/window만 tuning input에서 제외한 뒤 나머지 clean raw로 EV/runtime approval/LDM/live-auto 후보 생성을 계속한다. 전체 source-quality block은 preflight artifact missing/invalid, row/window exclusion 생성 실패, 또는 high-volume no-contract처럼 결손 row를 안정적으로 특정할 수 없는 경우에만 사용한다. Unknown-token finding만 있는 경우는 review warning으로 보존하되 즉시 tuning stop으로 해석하지 않는다.

`threshold_cycle_preopen_apply`는 통합 report뿐 아니라 `entry_ai_gate_backtest`, `scalping_pyramid_quality_calibration`, `scalping_avg_down_recovery_calibration` 같은 direct postclose calibration/backtest report를 읽을 때도 source-date의 `observation_source_quality_audit` preflight를 다시 확인한다. Postclose wrapper는 당일 pyramid feedback 생성 직후 source-quality preflight를 먼저 완료하고 그 다음 pyramid/avg-down calibration을 실행한다. 따라서 당일 감사 미생성 때문에 같은 날짜를 cumulative 입력에서 제외하지 않으며, 감사 실패 자체는 기존 fail-closed exclusion으로 보존한다. 각 누적 producer도 목표일 감사 하나로 과거 날짜를 대리하지 않고 clean-baseline window의 날짜별 preflight를 검사하며, missing/invalid/fail/blocked 날짜는 행을 읽기 전에 제외하고 `source_quality_excluded_dates`에 사유·artifact·load error를 남긴다. Preflight가 missing/fail/blocked이면 해당 direct-loader 후보는 `source_quality_blocked`, `allowed_runtime_apply=false`로 닫고 다음 PREOPEN env override를 만들지 않는다. 세 direct 누적 품질 후보는 `single_cumulative_quality_update` 계약을 요구하며 clean baseline 누적 window, 동일 `quality_update_id`, 최대 1건, post-apply attribution을 검증한다. Scale-in에서는 구조적 `scale_in_split_order_plan` 및 후단 `real_pyramid_scale_in_quality_guard_runtime`과 병존할 수 있지만, PYRAMID/AVG_DOWN 누적 품질 갱신끼리는 한 PREOPEN에 정확히 최대 1건만 선택한다. 계약 누락·범위/ID/개수 불일치·복수 갱신은 fail-closed한다. `post_probe_winner_recovery`는 일반 PYRAMID threshold와 분리된 `post_probe_recovery` 조작 지점이다. exact `profit_not_enough` blocker의 clean-baseline venue별 표본 10건과 양의 notional EV를 충족한 venue만 다음 PREOPEN deterministic `auto_bounded_live` 후보가 되며, 1주 추가만 허용한다. KRX/NXT/PREMARKET cohort는 서로의 근거를 재사용하지 않고 명시적인 false 값까지 env에 기록한다. 실제 1주 recovery 종료 표본이 venue별 20건에 도달한 뒤 비용 반영 EV가 비양수이면 해당 venue를 자동 제외하며, source-quality preflight 실패·날짜 불일치·필수 env 결손은 fail-closed한다. full residual, 1주 초과 수량, hard/broker/order/quantity/cooldown guard 우회, provider/bot 변경은 금지한다.

### 1.1 Sim/Real Evidence Authority Contract

Bucket/dimension tuning의 primary evidence는 `sim_probe_lifecycle_ev`다. `real 1-share` 표본은 해당 bucket policy가 실제 runtime에 매핑되어 적용된 post-apply cohort가 되기 전까지 primary EV evidence가 아니다. pre-apply real 표본은 `execution_quality_calibration`, `safety_veto`, `provenance_validation`, broker/fill/slippage source-quality 확인에만 사용할 수 있다. post-apply 이후 real 표본은 적용된 policy의 attribution anchor로만 해석한다.

자동화 tuning 후보와 AI Tier2 reviewer payload는 `evidence_authority_contract.primary_evidence_source=sim_probe_lifecycle_ev`, `mapped_runtime_policy_enabled`, `forbidden_uses`를 남겨야 한다. 금지 use는 `real_1share_as_preapply_primary_ev`, `real_one_share_as_preapply_primary_ev`, `merge_real_pnl_with_sim_probe_ev`, `runtime_change_from_preapply_real_sample`이다. AI나 deterministic reviewer가 pre-apply real 1-share PnL을 primary EV로 쓰거나 sim/probe EV와 합산하거나 threshold/order/provider/cap/bot 변경 근거로 쓰면 `source_quality_blocker`, `source_quality_gap`, `instrumentation_gap`, 또는 `reject`로 fail-closed한다.

Postclose chain은 direct predecessor artifact 계약을 갖는다. 후행 단계는 직전 JSON/Markdown artifact가 없거나 JSON 검증이 끝나지 않으면 `THRESHOLD_CYCLE_ARTIFACT_WAIT_SEC` 동안 대기하고, timeout 시 fail-closed한다. workorder source용 `threshold_cycle_ev` pre-pass와 workorder summary refresh용 post-pass를 분리하며, 최종 `threshold_cycle_postclose_verification`이 latest `START` 이후 wait/fail/timeout과 workorder `generation_id/source_hash/lineage`를 자동 점검한다. 같은 날짜 재생성 판정은 `mtime`이 아니라 `generation_id`, `source_hash`, `lineage.{new,removed,decision_changed}_order_ids`를 우선한다. Clean tuning baseline 이전 report/analytics 잔존물과 `observation_source_quality_audit` preflight 누락은 fail-closed한다. Preflight hard block 상태의 runtime-applicable 후보 또는 workorder handoff 누락도 fail-closed한다. LDM·Swing LDM·bottom-rebound source의 후보와 workorder는 각 downstream handoff가 완결되어야 한다. `producer_gap_discovery`는 wrapper DONE marker에서 해당 opt-in flag가 true인 실행에만 parsed AI와 workorder handoff를 검증한다. `runtime_apply_gap_audit`, `key_lineage_ledger`, `conversion_lane`은 각 실행 flag가 true인 경우 artifact·retry queue·key continuity를 검증하며, 필수 계약 누락은 fail-closed한다.

추가 generation 계약으로 최종 EV refresh 뒤 workorder를 다시 생성해 `source_fingerprint`의 size/SHA-256을 현재 source bytes와 닫은 뒤 runtime summary와 verifier를 실행한다. EV 안의 workorder 요약은 `diagnostic_previous_generation_not_ev_decision_input`이며 EV freshness의 역방향 권한이 아니다. verifier는 calibration/threshold AI review -> EV -> runtime summary 순서, workorder content fingerprint, 실행된 swing stage와 `strategy_scope` 일치를 함께 확인한다.

## 2.2 Source-Quality as Automation Input

report-only 산출물은 runtime mutation 권한이 없지만, source-quality 값은 자동화 체인의 입력으로 사용될 수 있다. `swing_pattern_lab_automation`/`threshold_cycle_ev`/workorder는 OFI/QI `stale_missing_flag`를 단일 boolean이 아니라 reason과 unique record 기준으로 노출한다.

## 2.3 Pipeline Event Source Contract

`pipeline_events_YYYY-MM-DD.jsonl`은 lossless forensic raw stream이고 `threshold_events_YYYY-MM-DD.jsonl`은 threshold-cycle compact decision stream이다. raw event count나 파일 크기는 source-quality/ops 입력으로만 사용하며, runtime family 승격/rollback은 report artifact, owner, sample floor, rollback guard를 통과해야 한다.

고빈도 diagnostic stage는 `metric_role=ops_volume_diagnostic`, `decision_authority=none`, `forbidden_uses=runtime_threshold_or_order_guard_mutation`으로 취급한다. `blocked_*` 반복 이벤트를 튜닝 입력으로 쓰려면 먼저 stage/date/stock/source-quality 단위 summary를 만들고, suppressed count 또는 sample rate를 명시해야 한다. 주문 제출/체결/exit/safety/provenance/source-quality transition은 throttle/compaction에서도 lossless 보존 대상이다.

BUY Sentinel v1 summary는 raw suppression 없이 `strength_momentum_observed`, `blocked_strength_momentum`, `blocked_swing_score_vpw`, `blocked_overbought`, `blocked_swing_gap`만 1분 bucket으로 집계한다. summary row는 `event_count`, `second_counts`, `field_presence_counts`, numeric stats, raw offset, deterministic sample을 포함하며 `decision_authority=diagnostic_aggregation`이다. `actual_order_submitted`, 주문/체결/청산, AI score, budget/latency/order lifecycle, provenance/source-quality transition은 기존 row cache에서 lossless로 유지한다. summary manifest가 없거나 stale이면 BUY Sentinel은 raw/cache 경로로 fallback한다.

스윙 entry lifecycle은 `selection -> entry policy -> submit quality -> holding/exit attribution` 단일 경로로 해석한다. `blocked_swing_score_vpw`, `blocked_swing_gap`, `blocked_gatekeeper_reject`, `market_regime_block`는 legacy hard-gate 근거가 아니라 `metric_role=baseline_prior_feature` 입력이며, `swing_entry_policy_evaluated`는 dry-run simulated submit 품질 경로로만 전달한다. Broker/account/order/quantity/cooldown/stale quote/latency DANGER/paused trading safety는 계속 fail-closed이고, final full-live conversion approval 전에는 full live 전환, cap release, provider 변경, bot restart 권한이 없다.

Pipeline Event Compaction V2는 producer-side compactor를 `PIPELINE_EVENT_HIGH_VOLUME_COMPACTION_MODE=off|shadow|suppress`로 노출하며 기본값은 `shadow`다. `shadow`는 raw JSONL/DB upsert를 그대로 유지하면서 `pipeline_event_producer_summary_YYYY-MM-DD.jsonl`과 manifest만 추가 생성하는 report-only 계측이다. raw-derived parity side는 `summary_detail_level=counts_only_v1`로 stage/reason/bucket identity, event count, first/last coverage만 저장하며 full diagnostic samples, second counts, numeric stats, raw offsets를 중복 저장하지 않는다. 기존 full-detail producer-parity manifest는 detail-level mismatch로 한 번 재생성된다. `off`는 장애 대응용으로 producer summary 생성을 끄는 옵션이다. `suppress`는 구현되어도 기본 비활성이고, raw-derived summary와 2영업일 이상 parity를 통과한 뒤 별도 workorder/approval owner가 열리기 전에는 사용하지 않는다. `pipeline_event_verbosity_report`의 state와 suppress eligibility는 ops/code-improvement 입력일 뿐 실주문 승인, threshold apply, EV primary metric 단독 근거가 아니다.

보관 정책은 runbook의 `Pipeline Event Verbosity/Retention Policy`를 따른다. tuning-monitoring late pass가 target-date parquet/backfill을 검증한 뒤 `compress_db_backfilled_files --days 0 --date TARGET_DATE`로 verified pipeline raw/snapshot을 압축한다. canonical AI context와 pipeline summary는 D+1 이후 JSONL/schema 또는 manifest 검증을 통과해야 하고, threshold partition은 완료 checkpoint가 있는 D+30 이후에만 gzip으로 전환한다. 각 소비자는 plain/gzip을 같은 계약으로 스트리밍하며 historical summary append는 먼저 archive를 rehydrate한다. gzip 복원 검증 전에는 원본을 제거하지 않는다. 정규 archive가 먼저 성공했으면 재실행은 no-op이며, 미검증 파일 삭제나 당일 raw 수동 삭제는 허용하지 않는다.

### Scalping Pre-AI Gate Risk Context Contract

| `liquidity_pre_submit_guard_p1` | `blocked_liquidity` risk context, `pre_submit_liquidity_guard_block` safety block, or `pre_submit_liquidity_guard_observed_greenfield_prior` when greenfield authority is active | risk context는 `runtime_effect=false`; pre-submit guard는 기본 `runtime_effect=pre_submit_block`; greenfield selected 시 submit bucket prior observation | AI input, counterfactual, broker submit safety, lifecycle bucket discovery |

`liquidity_gate_refined_candidate`와 `overbought_gate_refined_candidate`는 historical/reference family로 격하한다. 같은 `blocked_liquidity`/`blocked_overbought` 표본을 active calibration candidate로 두 번 만들지 않으며, 기존 source bundle metric은 각각 `liquidity_pre_submit_guard_p1`, `overbought_pullback_guard_p1`의 `source_metrics`로 승계한다. report consumer는 `supersedes` 필드를 보고 legacy family를 runtime/apply 후보가 아니라 migration lineage로만 해석한다.

공통 필드는 `metric_role`, `decision_authority`, `window_policy`, `sample_floor`, `primary_decision_metric`, `source_quality_gate`, `forbidden_uses`, `runtime_effect`를 선언한다. pre-AI risk context는 `metric_role=risk_context`, `decision_authority=source_quality_only`, `window_policy=same_day_intraday_light + rolling_5d attribution`, `sample_floor=20`, `primary_decision_metric=source_quality_adjusted_ev_pct after counterfactual`, `source_quality_gate=insufficient_history/stale_quote/extreme_sell_dominance`, `runtime_effect=false`다. `actual_order_submitted=false` 관찰 표본은 missed-upside/avoided-loss 분석 대상이지만 broker execution 품질이나 실주문 전환 근거로 단독 사용하지 않는다.

금지 사용처는 score threshold 전면 완화, fallback 재개, provider route 변경, 주문가 guard 완화, 스윙 dry-run 해제, approval 없는 broker order submit이다. `liquidity_pre_submit_guard_p1`과 `overbought_pullback_guard_p1`의 기본 pre-submit block은 주문 제출 직전 safety guard이며 threshold/provider/bot 상태를 바꾸지 않는다. `upper_limit_entry_proximity_guard`는 상한가 근접 추격매수를 막는 real-entry hard guard다. `rising_missed_one_share_entry`는 기본 `KORSTOCKSCAN_RISING_MISSED_UPPER_LIMIT_EXCLUDE_PCT=22.0` 이상이면 후보에서 제외하지만, 과거 `KORSTOCKSCAN_RISING_MISSED_SCOUT_ENTRY_BUDGET_CAP_KRW=400000`은 archive/config compatibility일 뿐 runtime sizing 권한이 없다. Rising Missed는 종목선정 lineage로서 중앙 `position_sizing_dynamic_formula`가 정한 총수량을 probe-first 첫 1주와 잔여 leg로 보존한다. 최종 real submit은 기본 `KORSTOCKSCAN_SCALP_UPPER_LIMIT_ENTRY_BLOCK_PCT=27.0` 이상이면 broker 주문 전 차단한다. Greenfield selected 상태에서는 `liquidity_pre_submit_guard_p1`과 `overbought_pullback_guard_p1`만 submit stage의 튜닝 prior로 남고, `upper_limit_entry_proximity_guard`는 hard guard로 유지된다. real submit authority는 promoted submit bucket이 소유한다.

### Scalping Entry ADM Advisory Contract

`scalp_entry_action_decision_matrix`는 스캘핑 entry에서 나쁜 feature를 단순 blacklist하는 report가 아니라 `BUY_NOW`, `WAIT_REQUOTE`, `SKIP_STALE`, `BUY_DEFENSIVE`, `NO_BUY_AI`, `SKIP_SOURCE_QUALITY`, `SKIP_PRE_SUBMIT_SAFETY` 중 어떤 action이 더 나았는지 비교하는 ADM source bundle이다. 산출물 계약은 `report_type=scalp_entry_action_decision_matrix`, `runtime_effect=false`, `decision_authority=entry_advisory_prompt_context_only`, `application_mode=operator_override_advisory_prompt`, `primary_decision_metric=source_quality_adjusted_ev_pct`다. 다만 사용자가 운영 override를 명시하면 runtime consumer는 이 source를 `entry_adm_runtime_bias_operator_override`로 읽어 `entry_adm_runtime_effect=force_wait|force_drop|buy_defensive_bias`를 AI 결과에 합성한다. `BUY_NOW`/`BUY_DEFENSIVE`는 positive action bucket도 튜닝 대상이지만, broker submit guard를 우회하거나 AI `WAIT/DROP`을 강제로 `BUY`로 승격하는 권한은 없다.

runtime 계측은 `scalp_entry_action_decision_snapshot` stage로 남긴다. snapshot은 `candidate_id`, `record_id`, `sim_record_id`, `ai_score`, `ai_action`, `chosen_action`, `eligible_actions`, `rejected_actions`, pre-AI risk context, submit revalidation age, orderbook spread/depth, price resolver 결과, `actual_order_submitted`, `broker_order_forbidden`을 포함한다. sim/probe/no-buy/counterfactual 표본은 항상 `actual_order_submitted=false`로 남기며, 실주문 post-sell source와 섞지 않는다.

AI prompt 반영은 `KORSTOCKSCAN_SCALP_ENTRY_ADM_ADVISORY_ENABLED=true`일 때 entry prompt에만 `[Entry ADM Advisory Context]`를 append한다. 기존 응답 schema는 바꾸지 않고 cache token에 `entry_adm:<matrix_version>:<bucket_token>`을 포함한다. 운영 override의 직접 영향도는 `KORSTOCKSCAN_SCALP_ENTRY_ADM_RUNTIME_BIAS_ENABLED=true`가 담당한다. matched bucket이 `SCALP_ENTRY_ADM_MIN_BUCKET_SAMPLE`/`SCALP_ENTRY_ADM_MIN_JOINED_SAMPLE`을 통과한 경우에만 dominant action이 `WAIT_REQUOTE/SKIP_STALE`이면 `BUY -> WAIT`, `NO_BUY_AI/SKIP_SOURCE_QUALITY/SKIP_PRE_SUBMIT_SAFETY`이면 `BUY -> DROP`, `BUY_NOW/BUY_DEFENSIVE` bucket의 `source_quality_adjusted_ev_pct < 0`이면 `BUY -> WAIT`로 보정한다. `KORSTOCKSCAN_SCALP_ENTRY_ADM_HYPOTHESIS_FALLBACK_ENABLED=true`는 stale high, source-quality blocker, low liquidity, weak momentum + chase risk 조합을 provenance로 남기며, `KORSTOCKSCAN_SCALP_ENTRY_ADM_HYPOTHESIS_FORCE_ENABLED=true`가 별도로 켜진 경우에만 WAIT/DROP action을 강제한다. stale quote, liquidity, overbought, latency, price freshness pre-submit safety guard는 여전히 ADM보다 우선한다.

### Lifecycle Decision Matrix Runtime Contract

`lifecycle_decision_matrix`는 고정 score bucket 정책이 아니라 개별 후보의 `runtime_features`와 사후 `labels`를 분리한 lifecycle row matrix다. runtime 입력 가능 feature는 AI score/action, microstructure, latency/source quality, price resolver, OFI/QI, position PnL/peak/held_sec, 현재 적용된 fixed threshold 값, scale-in add type/가격/수량 provenance, source-only institutional flow context로 제한하고, `mfe_10m_pct`, `mae_10m_pct`, `close_10m_pct`, realized profit, fill outcome, avoided loss, missed upside는 label 전용이다. runtime resolver는 label 필드를 읽지 않는다.

`lifecycle_ai_context`는 LDM/ADM을 hard gate로 쓰지 않고 OpenAI 판단에 공급하는 context-only layer다. 장후에는 먼저 `lifecycle_ai_context_attribution`이 전일 runtime provenance를 stage별로 집계하고, LDM policy entry에는 `context_contribution_score`, `bounded_auxiliary_weight`, `context_feedback_route`를 보조 feature로 붙인다. 그 다음 `lifecycle_ai_context`가 `[Lifecycle AI Context]` prompt text를 생성한다. 이 context는 `entry`, `holding`, `exit` AI prompt에만 append되며, `submit`과 `scale_in`은 artifact/provenance only다. 다음 PREOPEN selected env는 `KORSTOCKSCAN_LIFECYCLE_AI_CONTEXT_ENABLED=true`와 함께 `KORSTOCKSCAN_SCALP_ENTRY_ADM_RUNTIME_BIAS_ENABLED=false`, `KORSTOCKSCAN_HOLDING_EXIT_MATRIX_RUNTIME_BIAS_ENABLED=false`, `KORSTOCKSCAN_HOLDING_EXIT_MATRIX_SCALE_IN_BIAS_ENABLED=false`, `KORSTOCKSCAN_LIFECYCLE_DECISION_MATRIX_RUNTIME_EFFECT_ENABLED=false`를 명시해 deterministic mutation을 막는다.

`institutional_flow_context`는 Kiwoom access를 새 클라이언트로 분리하지 않는다. REST는 `kiwoom_utils.py`의 token cache와 `fetch_kiwoom_api_continuous()` helper를 재사용하고, WS는 `KiwoomWSManager`의 `0F` 외국계 거래원 추정값과 기존 `0w` 프로그램 매매 cache를 사용한다. report row는 `foreign_net_roll5`, `inst_net_roll5`, `dual_net_buy`, `smart_money_net`, `institutional_accumulation_score`, `institutional_flow_status/source/age`를 제공하지만 v1에서는 action을 바꾸지 않는다. `MISSING/STALE/PARSE_ERROR/PARTIAL/RATE_LIMITED/TOKEN_ERROR`는 source-quality provenance이며, stale/missing만으로 BUY/scale-in/exit를 확정하거나 threshold를 바꾸지 않는다.

스캘핑 sim scale-in 확대는 독립 정책이 아니라 matrix `scale_in` arm을 채우는 source actuator다. `PASSIVE_BASELINE`은 기존 resolver 가격의 체결/미체결 진단 cohort이고, `MARKETABLE_OBSERVATION`은 유효하고 stale하지 않은 best ask를 사용한 shadow tranche primary cohort다. 동일 판단은 exact `scale_in_decision_id`를 공유하며 canonical sim position은 NO_ADD control로 유지한다. LDM runtime sample은 `MARKETABLE_OBSERVATION + ADD_FILLED + exact v2 label`만 소비하고 passive/unavailable row는 sample floor를 채우지 않는다. 이 source는 `actual_order_submitted=false`, `broker_order_forbidden=true` authority를 유지하고 real scale-in 주문, cap 해제, hard safety 완화 근거로 단독 사용하지 않는다.

`fixed_threshold_contract`는 기존 threshold를 `hard_safety`, `baseline_prior`, `bounded_tunable`, `hard_safety_submit_quality`, `legacy_archive`로 분류한다. `hard_safety`에는 broker submit guard, stale quote submit block, price freshness, hard/protect/emergency stop, 계좌/order/cooldown/qty guard가 포함되며 matrix가 우회할 수 없다. `BUY_SCORE_THRESHOLD`, VPW/strength/momentum, entry cutoff는 baseline prior feature일 뿐 score 단독 action authority나 score 단조 EV 가정을 만들지 않는다. `score65_74_recovery_probe`는 artifact 호환용 family id를 유지하되 current runtime floor/effective range를 함께 기록하며 score60~74 bounded tunable로 취급한다. soft stop/holding flow, scale-in price guard도 bounded tunable로 남고 기존 bounds/max step/sample floor/source-quality gate를 통과해야 한다. latency DANGER/stale/broker submit 차단은 hard safety submit 품질 감사로 보고, CAUTION은 slippage check 이후 normal submit semantics다. fallback scout/main, fallback single, latency fallback split-entry, legacy latency composite, closed shadow axes는 archive로 분리되어 runtime feature로도 쓰지 않는다.

ADM 확장 관계는 `Wrap Then Replace`다. v1에서는 Entry ADM과 Holding/Exit ADM을 제거하지 않고 lifecycle runtime policy가 먼저 proposal을 만들며, 기존 ADM은 adapter/fallback으로 남는다. selected 전에는 기존 ADM env만 직접 작동하고, selected 후에는 lifecycle proposal이 `original_action`, `selected_action`, `fixed_threshold_role`, `safety_passthrough`를 함께 남겨 기존 ADM 보정과 safety block attribution을 한 row로 묶는다.

runtime 우선순위는 `hard safety veto -> account/order/broker guard -> lifecycle matrix runtime policy -> existing ADM adapter -> baseline fixed threshold fallback`이다. `lifecycle_decision_matrix_runtime` family가 selected되면 env는 policy file/version, promote enable, max promotes per day, min stage confidence만 전달한다. BUY 승격은 `BUY_DEFENSIVE` micro canary로 제한하고, submit/holding/scale-in/exit stage는 각 stage별 허용 action만 제안한다. 장중 threshold mutation, hard safety override, sim-only real execution 품질 주장, label future leakage는 금지한다.

### Holding/Exit ADM Runtime Bias Contract

`holding_exit_decision_matrix`는 운영 override에서 보유/청산 AI flow에도 직접 연결된다. `KORSTOCKSCAN_HOLDING_EXIT_MATRIX_RUNTIME_BIAS_ENABLED=true`이면 matrix bias가 `prefer_exit`일 때 `HOLD/TRIM -> EXIT`, `prefer_avg_down_wait` 또는 `prefer_pyramid_wait`일 때 `EXIT/DROP/SELL -> HOLD`로 보정할 수 있다. `TRIM -> HOLD`는 기본 차단이며 `KORSTOCKSCAN_HOLDING_EXIT_MATRIX_TRIM_TO_HOLD_ENABLED=true`가 별도로 켜진 경우에만 허용한다. matrix entry가 비어 있더라도 hypothesis fallback은 손실 구간의 `AVG_DOWN` 대기, 수익 구간의 `PYRAMID` 대기를 `holding_exit_matrix_scale_in_bias`로 남기고, `KORSTOCKSCAN_HOLDING_EXIT_MATRIX_SCALE_IN_BIAS_ENABLED=true`이면 scale-in evaluator가 `holding_exit_matrix_avg_down_bias` 또는 `holding_exit_matrix_pyramid_bias` action을 생성할 수 있다.

hard/protect/emergency stop, broker/account/order/cooldown/qty guard, stale quote, price freshness, receipt/provenance missing 같은 safety veto는 ADM보다 우선한다. scale-in 주문은 기존 `ENABLE_SCALE_IN`, 계좌 cap, cooldown, price resolver, spread, qty cap, swing canary approval guard를 통과해야 하며 ADM/LDM이 broker submit guard를 우회하지 않는다.

postclose consumer는 `threshold_cycle_ev`, `runtime_approval_summary`, `code_improvement_workorder`, `scalping_pattern_lab_automation`, `threshold_cycle_postclose_verification`, `artifact_freshness`다. `joined_sample < sample_floor`, `missing_action_bucket`, `source_quality_gap`, `prompt_context_not_loaded`는 live apply 후보가 아니라 `runtime_effect=false`, `allowed_runtime_apply=false` instrumentation/report workorder로만 생성한다.

### Runtime Approval Hard Gate Review Contract

`runtime_approval_summary`는 각 scalping/swing family에 `gate_review_class`, `legacy_hard_gate_risk`, `hard_gate_review`, `tuning_route`, `analysis_coverage`를 노출한다. 목적은 historical hard gate, 의도된 safety guard, runtime contract gap, same-stage owner conflict, sample/source-quality gap을 한 화면에서 분리해 보는 것이다.

분류 기준:

| 분류 | 의미 | 조치 |
| --- | --- | --- |
| `legacy_summary_superseded` | 과거 hard pre-AI gate family가 summary에 남은 경우 | active family의 `supersedes`/`source_metrics` lineage로만 해석하고 runtime/apply 후보에서 제외 |
| `intentional_safety_guard` | submit 직전 가격/유동성/과열/scale-in safety guard | AI/counterfactual 분석은 허용하되 broker submit guard는 fail-closed 유지 |
| `contract_gap` | 분석 표본은 있으나 runtime env key/guard/approval consumer가 없는 경우 | code-improvement workorder 또는 approval contract 설계가 먼저다 |
| `same_stage_deferred` | 같은 stage owner와 충돌해 보류된 경우 | active owner attribution이 닫힌 뒤 별도 approval route로 재검토 |
| `sample_or_contract_gap` / `source_quality_or_contract_gap` | 표본, source-quality, runtime guard가 부족한 경우 | source-quality blocker와 sample floor를 먼저 닫고 tuning 후보로 승격 |
| `no_unreviewed_hard_gate` | hard gate 잔존 문제가 아니라 selected/applied/advisory/approval-ready 축 | 기존 threshold-cycle 또는 approval route로 판정 |

이 분류는 read-only review metadata이며 `runtime_mutation_allowed=false`를 바꾸지 않는다. 특히 스윙 `swing_gatekeeper_accept_reject`는 `blocked_gatekeeper_reject`/`swing_probe_entry_candidate` 분석 표본이 있어도 accept/reject 자체 env guard가 없으면 `contract_gap`으로 남긴다. `swing_gatekeeper_reject_cooldown`과 `swing_model_floor`처럼 dry-run/final approval route가 있는 축은 hard gate 잔존이 아니라 승인/적용 절차 문제로 본다. Historical phase0 real-canary 축은 approval route가 아니라 legacy archive로 분류한다. `score_vpw/gap/gatekeeper` raw count는 `baseline_prior_feature`로만 분류하고 `SWING_ENTRY_DROUGHT_CRITICAL`의 hard-gate 병목 증거로 단독 사용하지 않는다.

## 2.4 LDM Bucket Handoff Contract

LDM `entry_bucket_attribution`은 `metric_role=sim_probe_ev`, `decision_authority=adm_ldm_entry_bucket_attribution_source_only`, `primary_decision_metric=source_quality_adjusted_ev_pct` 계약을 가진 source-only layer다. 자동화체인은 사람이 bucket을 수동 지정하지 않아도 `score_band`, `source_stage`, `chosen_action`, `stale_bucket`, `liquidity_bucket`, `strength_bucket`, `overbought_bucket`, `time_bucket`, `exit_rule`, `combo_entry_spot`을 생성한다.

핸드오프 규칙은 fail-closed다. LDM 후보가 있으면 `threshold_cycle_ev`와 `runtime_approval_summary`는 `entry_bucket_runtime_approval_candidates`를 보여야 하고, LDM workorder가 있으면 `code_improvement_workorder`는 `lifecycle_decision_matrix_entry_bucket_attribution` order를 생성해야 한다. 누락되면 postclose verifier가 `ldm_entry_bucket_handoff_missing`으로 실패한다. 이 실패는 전략 edge 판정이 아니라 선행 artifact/consumer 단절 판정이며, grace 이후 재시도해도 선행 산출물이 없으면 FAIL이다.

LDM `submit_bucket_attribution`은 `metric_role=submit_funnel_source_quality_gate`, `decision_authority=adm_ldm_submit_bucket_attribution_source_only`, `primary_decision_metric=source_quality_adjusted_ev_pct` 계약을 가진 source-only layer다. 자동화체인은 `submit_source_stage`, `revalidation_state`, `quote_age_bucket`, `price_resolution_bucket`, `would_limit_fill`, `actual_order_submitted`, `broker_order_forbidden`, `liquidity_guard_action`, `liquidity_bucket`, `overbought_guard_action`, `overbought_bucket`, `latency_state`, `latency_reason`, `pre_submit_refresh_source`, `pre_submit_refresh_attempted`, `pre_submit_refresh_applied`, `pre_submit_refresh_reason`, `pre_submit_refresh_age_bucket`, `quote_freshness_resolution_state`, `price_below_bid_bucket`, `combo_submit_quality`를 생성한다. `pre_submit_quote_refresh`와 `pre_submit_ws_snapshot_refresh`는 BUY/submit drought quote freshness attribution의 하위 원인 필드이며, real pre-submit event에 기록된 provenance만 사용한다. sim/probe/counterfactual submit-path는 live WS 조회를 수행하지 않고 `sim_submit_path_not_applicable` 또는 recorded provenance only로 남기며 `runtime_effect=false`, `decision_authority=submit_drought_quote_freshness_attribution_only` 또는 기존 sim submit observation authority를 유지한다. sim submit-path는 `scalp_sim_pre_submit_liquidity_guard_would_block/pass/unknown`과 `scalp_sim_pre_submit_overbought_guard_would_block/pass`로 real pre-submit guard의 counterfactual verdict를 남기며, `WOULD_BLOCK`이어도 sim 가상체결 흐름은 계속 진행한다. real submit-path와 sim submit-path는 shared pre-submit guard evaluator의 liquidity/overbought verdict를 사용해야 하며, real은 `pre_submit_*_guard_action=BLOCK/PASS/UNKNOWN`과 LDM bucket용 `*_guard_action=WOULD_*`를 함께 남긴다. 이 verdict는 `latency_pass`, guard block, price block, order leg, order bundle, sim virtual pending/fill/holding/sell completion까지 전파되어 downstream attribution에서 submit 이후 흐름과 끊기지 않아야 한다. liquidity source가 없으면 pass로 취급하지 않고 `WOULD_UNKNOWN` source-quality bucket으로 남긴다. sim verdict는 `actual_order_submitted=false`, `broker_order_forbidden=true`, `runtime_effect=false`, `decision_authority=sim_submit_path_observation_only`인 관찰 label이며 broker submit, threshold, provider, bot restart 권한이 없다. `submitted_order_price=0`과 stale revalidation이 함께 있는 sim submit-path row는 `sim_unpriced_stale_warning`으로 보존하되 dynamic entry price fill/EV denominator에서 제외한다. Source-quality audit는 stage 이름과 `WOULD_*` action, authority/provenance 값이 서로 맞지 않으면 contract fail로 분류한다. post-entry 약한 계약은 `order_entry_post_submit_contract_gap_review`, `order_entry_broker_receipt_contract_gap_review`, `order_entry_fill_quality_contract_gap_review`, `order_entry_telegram_post_submit_contract_gap_review`, `order_entry_source_taxonomy_contract_gap_review`, `order_entry_sim_submit_path_bucket_instrumentation`으로 분리하며 broker submit guard, Telegram BUY 알림, provider route, threshold, bot restart를 직접 변경하지 않는다.

submit 핸드오프도 fail-closed다. `SUBMIT_DROUGHT_CRITICAL`이 있으면 `code_improvement_workorder`는 `order_entry_submit_drought_auto_resolution`과 위 weak-contract order를 selected에 포함해야 하고, LDM은 `submit_bucket_attribution`을 생성해야 하며, `threshold_cycle_ev`와 `runtime_approval_summary`는 `buy_funnel_sentinel_primary`, `entry_submit_drought_handoff_selected`, submit attribution summary를 보여야 한다. 누락되면 postclose verifier가 `buy_funnel_submit_drought_handoff_missing` 또는 `ldm_submit_bucket_handoff_missing`으로 실패한다.

LDM `scale_in_bucket_attribution`은 `metric_role=sim_probe_ev`, `decision_authority=adm_ldm_scale_in_bucket_attribution_source_only`, `primary_decision_metric=source_quality_adjusted_ev_pct` 계약을 가진 source-only layer다. 자동화체인은 `AVG_DOWN/PYRAMID` arm을 분리하고 `blocker_namespace`, `blocker_reason`, `profit_band`, `peak_profit_band`, `held_bucket`, `ai_score_band`, `ai_score_source`, `supply_pass_bucket`, `price_guard_reason`, `qty_reason`, `time_bucket`을 생성한다. `hold_sec_out_of_range`는 AVG_DOWN-only blocker로 해석하고, PYRAMID 후보에서 reversal-add namespace를 쓰지 않는다.

`late_loss_avg_down_quote_recovery_defer`는 실시간 SCALPING 최종 손실 청산 직전 `late_loss_avg_down_retry` 후보가 열렸지만 추가매수 제출이 `invalid_quote`, `quote_stale`, `quote_consistency_*` 등 호가/가격 신뢰성 사유로만 막힌 경우의 bounded runtime guard다. 기본 유예는 90초(`KORSTOCKSCAN_SCALP_LATE_LOSS_AVG_DOWN_QUOTE_RECOVERY_DEFER_SEC`)이며, 유예 중에는 매도 fall-through를 차단하고 다음 루프에서 호가 재검증 및 AVG_DOWN 재시도를 우선한다. `late_loss_avg_down_retry`는 불리하지만 fresh한 micro VWAP threshold만 우회할 수 있고, `reversal_feature_source_quality`가 stale/missing provenance이면 `micro_context_stale:*`로 fail-closed되어 유예/재시도 근거가 될 수 없다. 손실이 비상 기준(`KORSTOCKSCAN_SCALP_LATE_LOSS_AVG_DOWN_QUOTE_RECOVERY_EMERGENCY_PCT`, 기본 -5.0%) 이하이거나 유예 만료 후에도 제출이 막히면 보호청산 경로를 다시 허용한다. 이 이벤트는 `metric_role=bounded_tunable`, `decision_authority=real_scalping_final_loss_sell_intercept`, `primary_decision_metric=mfe_giveback_pct` 계약을 따르며, broker guard bypass, hard safety bypass, provider/threshold/order price/quantity 변경 근거로 사용할 수 없다.

scale-in 핸드오프도 fail-closed다. LDM 후보가 있으면 `threshold_cycle_ev`와 `runtime_approval_summary`는 `scale_in_bucket_runtime_approval_candidates`를 보여야 하고, LDM workorder가 있으면 `code_improvement_workorder`는 `lifecycle_decision_matrix_scale_in_bucket_attribution` order를 생성해야 한다. source row가 있는데 attribution이 없으면 `ldm_scale_in_bucket_attribution_missing`, downstream 소비가 누락되면 `ldm_scale_in_bucket_handoff_missing`으로 실패한다. real `SCALPING_PYRAMID_*` quality 값은 `scalping_pyramid_quality_calibration -> threshold_cycle_preopen_apply`의 다음 PREOPEN bounded env 경로로만 자동 변경될 수 있고, `REVERSAL_ADD_*`와 PYRAMID cap/quantity 계열은 별도 승인 family가 없으면 bounded-tunable 후보/source-only로만 분류한다.


## 2.5 Codebase Performance Workorder Contract

`codebase_performance_workorder_report`는 기본 OFF다. `THRESHOLD_CYCLE_RUN_CODEBASE_PERFORMANCE_WORKORDER_REPORT=true`로 명시적으로 실행한 경우에만 `docs/codebase-performance-bottleneck-analysis.md`의 성능개선 후보를 source artifact로 만든다. accepted 후보는 Codex workorder runner safe scope에서 자동 구현 후보가 될 수 있지만 모든 후보는 `runtime_effect=false`, `strategy_effect=false`, `data_quality_effect=false`, `tuning_axis_effect=false`와 parity contract를 가져야 한다.

Legacy dashboard DB pool 후보는 DB 경로 제거로 더 이상 생성하지 않는다.

## 2.6 Metric Decision Contract

자동화 체인이 소비하는 새 관찰지표와 새 report section은 생성 시점에 판정 계약을 함께 선언해야 한다. 계약이 없으면 해당 지표는 `instrumentation_gap` 또는 `source_quality_blocker`로만 라우팅하고, threshold candidate, approval request, runtime env apply 입력으로 쓰지 않는다.

필수 필드는 아래와 같다.

| 필드 | 의미 |
| --- | --- |
| `metric_role` | 지표의 판정 역할. 아래 role taxonomy 중 하나 이상을 명시한다 |
| `metric_definition` | 분자/분모, 집계 단위, 포함/제외 조건, provenance field |
| `decision_authority` | `real_only`, `main_only_completed`, `sim_equal_weight`, `probe_observe_only`, `combined_diagnostic`, `source_quality_only`, `counterfactual_only` 중 하나 |
| `window_policy` | `daily_only`, `rolling_3d`, `rolling_5d`, `rolling_10d`, `cumulative_since_owner_start`, `post_apply_version_window`, `same_day_intraday_light` 중 primary/secondary window |
| `sample_floor` | hard 판정 최소 표본과 denominator. 표본 미달 시 `hold_sample` 또는 `report_only_calibration`으로 fail-closed |
| `primary_decision_metric` | 자동화 판정에 쓰는 단일 primary metric. EV 계열이면 필드명을 EV로 명확히 쓴다 |
| `secondary_diagnostics` | win rate, blocker share, active recovery, funnel count처럼 primary를 보조하는 지표 |
| `source_quality_gate` | freshness, missing, duplicate, stage provenance, real/sim/probe split 조건 |
| `runtime_effect` | 기본값은 `runtime_effect=false`. runtime 변경 가능 시 approval artifact, env key, rollback guard, same-stage owner rule을 함께 명시 |
| `forbidden_uses` | 단독 live 승인, real-like EV 합산, daily-only apply 등 금지 사용처 |

`metric_role` taxonomy는 아래 기준으로 고정한다.

| metric_role | 판정 용도 | 금지선 |
| --- | --- | --- |
| `primary_ev` | 기대값/순이익 개선 여부의 primary 판정. `equal_weight_avg_profit_pct`, `notional_weighted_ev_pct`, `source_quality_adjusted_ev_pct` 중 하나로 명명한다 | `win_rate` 또는 단순 합산값으로 대체 금지 |
| `diagnostic_win_rate` | 방향성/일관성/꼬리 리스크 보조 진단 | 단독 approval/live/canary 승격 금지 |
| `funnel_count` | 참여율, blocker, coverage, submitted drought 판단 | 손익 edge 또는 live 승인 근거로 단독 사용 금지 |
| `safety_veto` | severe loss, 주문 실패, provenance 손상, hard/protect/emergency stop 지연 차단 | 기대값 개선 지표로 사용 금지 |
| `source_quality_gate` | stale/missing/duplicate/provenance 품질 gate | edge 또는 threshold 추천값으로 사용 금지 |
| `active_unrealized` | open sim/probe 회복률, active position context | closed EV로 해석하거나 realized PnL과 합산 금지 |
| `execution_quality_real_only` | 브로커 체결/취소/receipt 품질 | sim/probe/combined 진단으로 대체 금지 |
| `sim_probe_ev` | sim/probe equal-weight 기대값 관찰 | real execution 품질 또는 실주문 전환 근거로 단독 사용 금지 |
| `risk_regime_state` | 패닉/시장상태처럼 매매 가능 행동의 범위를 해석하는 상태값 | approval artifact와 rollback guard 없이 주문, 청산, threshold, provider, bot 상태를 직접 변경 금지 |

window 해석은 아래처럼 분리한다.

| window_policy | 허용 용도 |
| --- | --- |
| `daily_only` | incident, safety veto, freshness/source-quality, same-day operational trigger. edge apply 승인에는 단독 사용 금지 |
| `rolling_3d` / `rolling_5d` / `rolling_10d` | 방향성 지속성, step size, candidate persistence |
| `cumulative_since_owner_start` | owner/canary baseline 누적 성과와 rollback guard 판정 |
| `post_apply_version_window` | threshold version별 applied/not-applied attribution |
| `same_day_intraday_light` | Sentinel/ops 상태 확인. threshold/live candidate 승격 금지 |

판정 규칙은 다음을 따른다.

1. `win_rate`는 `diagnostic_win_rate`다. 기대값/순이익 목표의 primary 판정은 `primary_ev`가 맡는다.
2. 단순 손익 합산은 EV가 아니다. 필드명은 `simple_sum_profit_pct`로 쓰고, EV 판정 필드는 `equal_weight_avg_profit_pct`, `notional_weighted_ev_pct`, `source_quality_adjusted_ev_pct` 중 하나를 사용한다.
3. `sim_equal_weight`, `probe_observe_only`, `counterfactual_only`, `combined_diagnostic` 권한 지표는 source bundle, approval request, workorder evidence에는 들어갈 수 있지만 broker execution 품질이나 실주문 전환 근거로 단독 사용하지 않는다.
4. `sim/probe/counterfactual` 예산은 실주문 주문가능금액과 분리한다. 실주문 경로는 `blocked_zero_qty`/broker budget guard를 유지하지만, `actual_order_submitted=false` 관찰축은 기본 `SIM_VIRTUAL_BUDGET_KRW=10,000,000`을 가상 주문가능금액으로 두고 실주문과 동일한 `entry_type_5stage_cap25_v1` 분류기를 탄다. provenance는 `virtual_budget_override=true`, `budget_authority=sim_virtual_not_real_orderable_amount`, `qty_source=scalping_position_sizing_allocator`, 그리고 중앙 sizing event 필드를 남긴다. 이 값은 real buying power, broker execution 품질, 실주문 가능 여부로 해석하지 않는다.
5. `position_sizing_dynamic_formula`는 모든 `SCALPING/SCALP` 신규·추가매수와 sim/counterfactual 수량의 단일 owner다. 선택 공식 `entry_type_5stage_cap25_v1`은 KRX 진입 기준시각과 정규화된 source 수로 `10%/15%/20%/25%/25%`를 선택하고 NXT·unknown·복원 실패는 10%로 fail closed한다. entry sizing은 current `stock/runtime`의 explicit KRX/NXT provenance만 사용하며, prior `OFF_SESSION` marker는 current explicit venue를 가리지 못한다. KRX/NXT explicit 값이 충돌하거나 모두 없으면 `venue=UNKNOWN`, `venue_resolution=conflicting_explicit_venue|missing_tradable_explicit_venue`로 1단계 10%에 닫는다. report candidate grid는 선택 공식과 `flat_10_fallback`만 비교한다. 과거 일곱 score-linear/보정 후보와 Rising Missed 400,000 KRW cap은 archive/parser compatibility만 가진다. primary metric은 `notional_weighted_ev_pct` 또는 `source_quality_adjusted_ev_pct`만 허용하며, 상세 계약은 [workorder-position-sizing-dynamic-formula](./workorder-position-sizing-dynamic-formula.md)가 소유한다. sim/probe 단독으로 실주문 수량 확대를 승인할 수 없다.
6. Entry `position_sizing_dynamic_formula`의 outcome-only notional 귀속은 동일 trace·symbol·venue·session의 exact broker 주문번호별 제출수량을 중복 제거해 합산한 값이 계획 `effective_qty`와 정확히 같을 때만 허용한다. 일반 probe-first는 `probe_submitted` 1주와 후속 `residual_submitted` 잔량의 합으로 계약을 닫을 수 있지만, terminal `one_share_exploration`처럼 합계가 계획수량보다 작은 표본은 `allocator_provenance_partial_submission_observation_only`로 남기고 standardized one-share 관찰만 허용한다. 계획 `effective_qty`를 probe 실제 제출수량으로 대체하거나 partial 표본을 `notional_net_profit_eligible`·economic promotion evidence로 사용하는 것은 금지한다.
7. `daily`, `rolling`, `cumulative`가 필요한 family에서 daily-only 악화/개선은 safety veto 또는 calibration trigger로만 쓰고, edge apply 승인은 rolling/cumulative와 source-quality gate가 닫힌 뒤에만 허용한다.
8. 새 관찰지표가 위 필드를 갖지 않으면 자동화 체인은 `hold_sample`, `hold_no_edge`, `source_quality_blocker`, `instrumentation_gap` 중 하나로 닫고 threshold mutation을 만들지 않는다.

새 관찰지표 onboarding은 아래 10개 항목이 모두 닫힌 뒤에만 자동화 source bundle에 편입한다.

| 항목 | 필수 결정 |
| --- | --- |
| 1 | `metric_role` |
| 2 | `decision_authority` |
| 3 | `window_policy` |
| 4 | `primary_decision_metric`과 `secondary_diagnostics` 분리 |
| 5 | `sample_floor`와 denominator |
| 6 | source-quality/provenance gate |
| 7 | forbidden automation / forbidden live uses |
| 8 | consumer와 owner |
| 9 | JSON/Markdown field names |
| 10 | fail-closed behavior |

## 2.7 Sim-to-Live Approval Contract

sim/probe 결과는 source bundle, approval request, workorder evidence에는 들어갈 수 있지만 live 반영에는 반드시 별도 계약이 필요하다. 일반 pre-final 최소 계약은 parsed AI Tier2 review, `preopen env key mapping`, `runtime guard`, `rollback/provenance`, `real/sim metric split`이다. Swing phase0 one-share/scale-in real-canary contracts are removed; historical artifacts are ignored and may only appear as legacy warnings.

현재 활성 연결부와 apply 상태는 Plan Rebase §7~§8 및 당일 checklist를 따른다. approval 요청 후보는 `approval_contract_status`, `approval_live_ready`, `approval_artifact_path`, `approval_contract_missing_components`, `approval_mode`를 함께 노출해야 한다. 제거된 family와 과거 audit는 archive evidence이며 current apply owner가 아니다. source와 running runtime을 구분하고, `runtime_apply_allowed=false` 또는 missing-contract 축은 artifact loader·env mapping·runtime guard가 닫히기 전까지 live 반영하지 않는다.

| `TRAILING_EARLY_EXIT` | trailing missed-upside/winner wide-window review | protect/trailing family owner와 rollback guard가 닫힌 `R3_manifest_only` 후보 | trailing threshold runtime mutation |

Sentinel은 report JSON/Markdown과 classification만 갱신한다. 날짜별 Telegram notify state는 운영하지 않으며, alert가 필요한 시스템 장애는 System Error Detector가 소유한다.

### 3.1 Panic Sell Defense Routing Standard

| panic_state | 기본 라우팅 | threshold-cycle 연결 조건 | 금지된 자동변경 |
| --- | --- | --- | --- |
| `NORMAL` | no-action | 없음 | 없음 |
| `PANIC_SELL` | 신규 live 진입 완화 금지 후보, stop-loss cluster attribution | V2 1차 후보는 `panic_entry_freeze_guard`다. approval artifact, rollback guard, runtime env key가 닫힌 뒤 다음 장전 pre-submit freeze canary로만 검토한다. `panic_stop_confirmation`은 후순위 | score threshold 완화, stop-loss 완화, 자동매도, bot restart |
| `RECOVERY_WATCH` | 회복 evidence 관찰, missed upside/방어효과 분리 | active sim/probe 평균 미실현 수익률 또는 post-sell rebound가 유지되고 provenance pass일 때 report-only 후보 유지 | live threshold mutation, 스윙 실주문 전환 |
| `RECOVERY_CONFIRMED` | `panic_rebound_probe` 후보 검토 | sim/probe only, `actual_order_submitted=false`, `broker_order_forbidden=true`, 장후 attribution과 다음 장전 bounded guard 필요 | broker order 제출, removed swing phase0 real-canary stage 재개 |

`panic_regime_mode`는 `panic_state`를 매매 로직에 직접 덮어쓰는 실행 신호가 아니라 risk-regime 해석 계층이다. metric contract는 `metric_role=risk_regime_state`, `decision_authority=source_quality_only` until approval artifact, `window_policy=same_day_intraday_light + postclose_attribution + next_preopen_apply`, `sample_floor=panic report freshness <= 5m and microstructure breadth floor when used`, `primary_decision_metric=source_quality_adjusted_avoided_loss_vs_missed_upside_ev_pct` for implemented guard attribution, `source_quality_gate=panic report provenance + real/sim/probe split + market/breadth confirmation`, `runtime_effect=false by default`, `forbidden_uses=auto_sell, stop_loss_relaxation, threshold_relaxation, provider_route_change, bot_restart, swing_real_order_enable`이다.

| panic_regime_mode | 입력 상태 | 허용되는 해석 | runtime 전환 조건 |
| --- | --- | --- | --- |
| `NORMAL` | `panic_state=NORMAL`, confirmed risk-off 없음 | 기존 selected family 유지 | 없음 |
| `PANIC_DETECTED` | `PANIC_SELL` 또는 confirmed risk-off/stop-loss cluster | 신규 위험 증가 금지 후보. AI BUY 판단은 기록하되 `blocked_by_panic` attribution 후보로 분리 | V2.0 `panic_entry_freeze_guard`만 approval artifact, env key, rollback guard, same-stage owner rule 완료 후 다음 장전 entry pre-submit canary 가능 |

패닉 lifecycle 확장은 단계별 owner를 분리한다. V2.0은 `panic_entry_freeze_guard`로 scalping 신규 BUY pre-submit 차단만 다룬다. V2.1의 미체결 진입 주문 cancel guard, V2.2의 holding/exit `panic_context` 반영, V2.3의 강제 축소/청산 guard는 각각 별도 workorder, approval artifact, rollback guard가 필요하며 V2.0 승인과 자동으로 묶지 않는다.

`panic_sell_defense_report`는 장중 cron으로 2분 offset 주기 생성하고, postclose wrapper가 threshold-cycle canonical report 생성 직전에 한 번 더 재생성한다. pipeline JSONL은 전량 list로 materialize하지 않고 단일 pass로 읽으며, exit/non-real provenance와 종목별 bounded detector state만 보존한다. 동일 lifecycle의 반복 `exit_signal`은 polling 횟수가 아니라 고유 broker sell order identity 수로 축약하고 `duplicate_real_exit_signal_count`를 별도 보존한다. `input_streaming`은 scanned/retained row, ordering gap, full-list 미생성 계약을 남긴다. 이 산출물은 microstructure risk-off/recovery signal, stop-loss cluster, active sim/probe recovery, post-sell rebound를 같은 source bundle에 고정할 뿐 runtime mutation 권한은 없다.

`notify_panic_state_transition`의 `panic_sell`과 `market_weakness`는 서로 다른 alert state owner다. `panic_sell`은 `PANIC_SELL`만 active로 취급하며, `RECOVERY_WATCH`와 broad/single-market breadth 약세를 패닉 시작으로 승격하지 않는다. `market_weakness`는 같은 날짜의 fresh non-empty observation ID와 source-only authority 계약만 소비한다. hysteresis는 exact-date reviewed policy가 없으면 listing market별 2회 activation/3회 release baseline이며, 유효한 정책이 있으면 observation에 고정된 activation 2~4·release 2~5 값을 사용한다. KOSPI single-market 관측 다음 KOSDAQ single-market 관측은 같은 activation streak가 아니며, single-market latch는 동일 market의 `recovery_evidence_markets`가 정책상 release 횟수 연속 확인될 때만 해제된다. `NEAR_WEAKNESS_BOUNDARY`, duplicate·60초 미만 observation, source-quality/identity/authority/policy-hash blocked observation은 임의로 전역 회복으로 보간하지 않는다. 현재 wrapper의 market-weakness audience 기본값은 admin이며 Telegram 발송이 꺼져도 `--observe-only`로 canonical weakness state를 계속 전진시킨다. notifier와 장후 response attribution 자체에는 주문·취소·청산·당일 threshold 변경 권한이 없다. 다만 `2026-08-31` 사용자 승인으로 분리된 `WIDGET_EPISODE_MARKET_WEAKNESS_ENTRY_FREEZE_OPEN_BUY_CANCEL_V2` consumer만 current-session market latch를 위젯·에피소드 신규·추가 BUY veto와 exact-owner broker-reconciled 미체결 BUY 잔량 취소에 소비한다. 다른 owner·수동 주문·SELL/target·보유 lifecycle에는 영향을 주지 않는다.

`micro_cusum_observer`는 OFI z-score CUSUM과 2-of-N micro consensus를 `source_quality_gate` / `source_quality_only` / `intraday_observe_only` 계약으로만 노출한다. `primary_decision_metric`이 아니며 `runtime_threshold_apply`, 주문 제출, 자동매도/자동매수, bot restart, provider route 변경 근거로 사용할 수 없다.

`microstructure_market_context`는 개별 보유/관찰 종목군에서 나온 micro risk-off가 전체 지수/breadth로 확인되는지 검증하는 source-quality gate다. `confirmed_micro_risk_off_advisory=true`는 시장 snapshot `RISK_OFF` 또는 평가 종목수 `20`개 이상과 risk-off 비율 `20%` 이상일 때만 가능하다. `market_panic_breadth.risk_off_advisory=true`는 KOSPI/KOSDAQ weighted composite index/stock breadth 기준이며, 한 시장만 급락/급등한 경우는 `single_market_risk_off_advisory` 또는 `single_market_risk_on_advisory`로 분리한다. 확인되지 않은 국소 risk-off는 `portfolio_local_risk_off_only=true`와 `source_quality_blockers`로 downstream attribution에 전달하고, panic runtime approval은 `freeze` 또는 follow-up 후보로만 해석한다.

스캘핑 sim-only `scalp_sim_panic_lifecycle`은 이 context를 `lifecycle_decision_matrix_runtime`의 `risk_regime_context`로 소비한다. `panic_level>=2` 또는 liquidity broken은 방어 actuator로 entry block과 holding 축소/청산을 허용한다. 반면 `panic_level=1` market breadth risk-off의 entry는 fixed hard gate가 아니라 관찰 regime이다. 개별 종목 feature가 `symbol_regime=BOTTOMING`으로 판정되면 `scalp_sim_panic_bottoming_entry_allowed`, 그렇지 않으면 `scalp_sim_panic_level1_entry_observed`로 sim-only entry row를 남기며, 두 경우 모두 lifecycle matrix의 entry feature로 소비한다. level 1의 scale-in block/holding tighten/조건부 partial sell은 entry 관찰과 별도 방어 actuator로 attribution을 분리한다. 이 경우 모든 event는 `source_family=panic_lifecycle_actuator`, `family_type=sim_lifecycle_source`, `live_selectable=false`, `preopen_apply_allowed=false`, `env_apply_allowed=false`, `threshold_env_mutation_allowed=false`, `real_order_allowed=false`, `actual_order_submitted=false`, `broker_order_forbidden=true`, `decision_authority=sim_observation_only`를 유지한다. `threshold_family=panic_lifecycle_actuator`는 registry backward-compatible routing key일 뿐 standalone live threshold family가 아니다. 이 경로는 real broker submit, Telegram BUY 알림, threshold/provider/bot 변경 권한이 없다.

`panic_entry_freeze_guard`는 compatibility/read-only approval 후보명이며 live-selectable threshold family가 아니다. 신규 runtime/matrix row에서는 `panic_entry_sim_context_freeze_observer` 성격의 sim lifecycle source로만 해석한다. artifact가 있어도 standalone preopen env, threshold mutation, provider route, bot restart trigger를 만들 수 없고, 기존 보유 청산, stop-loss, trailing, 스윙 실주문에는 영향을 주지 않는다.

### 3.2 Removed Panic-Buying Feature

The panic-buying detector/report, intraday wrapper, postclose producer, source-bundle consumer, approval/workorder bridge, sim euphoria actuator, and real-entry price modifier were removed on `2026-08-08`. Historical `data/report/panic_buying` artifacts remain archive/audit evidence only. No CLI, environment override, cron, PREOPEN family, runtime hook, or reactivation path remains.

A future rebound/exhaustion strategy must use a new namespace, event journal, source-quality contract, workorder, tests, and approval boundary. It must not consume or reinterpret the retired panic-buying artifacts.

Panic Telegram notices consume only `PANIC_SELL` start/release transitions. `notify_panic_state_transition` keeps panic alert state in `tmp/panic_state_telegram_notify_state.json` and the independent canonical weakness latch in `tmp/market_weakness_observer_state.json`. Panic release still requires two consecutive non-panic observations; ongoing market breadth weakness is represented by the separate market-weakness latch, whose release requires the observation-bound exact policy count of unique source-qualified recovery-margin observations (baseline three). This separation prevents `RECOVERY_WATCH` or one-market weakness from being mislabeled as a panic start without weakening the market-weakness release guard.
## 4. auto bounded calibration gate

`R5_bounded_calibrated_apply`는 완전 무인으로 실행하되 아래 조건을 deterministic guard와 AI correction guard가 매일 자동 확인한다.

1. 후보 family별 sample floor와 current/recommended diff가 report에 존재한다.
2. `daily`, `rolling`, `cumulative`가 같은 방향을 가리키고, 그 방향은 `diagnostic_win_rate`나 `simple_sum_profit_pct`가 아니라 family 계약의 `primary_ev` metric으로 확인된다.
3. `main-only`, `normal_only`, `post_fallback_deprecation` cohort를 분리할 수 있다.
4. full fill과 partial fill이 섞여 있으면 손익 결론을 hard 승인 근거로 쓰지 않는다.
5. 같은 stage의 live owner가 하나만 존재한다.
6. safety guard owner, env key, 봇 기동 시 runtime env source 절차가 문서화되어 있다.
7. apply plan은 장중 mutation이 아니라 다음 장전 runtime env manifest로만 반영된다.
8. 적용 후 threshold version별 post-apply attribution과 daily EV report가 생성된다.
9. 조건 미달은 다음 manifest의 `calibration_state`로 조정한다. safety guard 위반 시에만 `safety_revert_required=true`로 원복 후보 처리한다.

현재 auto-bounded calibration 후보군은 Plan Rebase §7~§8과 당일 PREOPEN apply artifact가 소유한다. 후보군 포함 자체는 apply 승인이 아니며, selected family만 policy/version/bounds를 다음 PREOPEN env로 전달한다. calibration source는 `threshold_cycle` compact event, BUY·ADM/lifecycle·보유/청산 report 요약과 창별 `calibration_source_bundle_by_window`를 사용한다. 제거되었거나 consumer가 없는 report-only source는 current source bundle과 traceability inventory에서 제외한다.

`calibration_source_bundle.report_only_cleanup_audit`는 source bundle consumer가 없는 report-only/legacy 산출물을 매 실행마다 `source_quality_gate`로 감사한다. 현재 관리 대상은 `sentinel_followup`, 정기 full snapshot에서 제외된 legacy `add_blocked_lock`, 제거된 `preclose_sell_target`이다. `cleanup_candidate_count > 0`이면 source-quality warning과 정리 후보로 표면화하지만, 이 audit는 `source_quality_only`이며 runtime threshold, 주문, 자동매수/자동매도, bot restart, provider route 변경 권한이 없다.

다음 장전 apply 후보는 deterministic/parsed-AI/same-stage guard가 닫힌 family만 인정한다. 일반 스윙 dry-run request는 `dry_run_auto_apply_ready` pre-final auto approval이면 별도 user artifact 없이 env apply 대상이 될 수 있다. 제거된 real canary와 과거 approval artifact는 current 후보로 노출하지 않는다. Final full-live/cap/provider/bot/safety 변경만 user approval artifact가 필요하다.

`pre_submit_price_guard` family에는 broker 제출 직전 safety 차단인 `pre_submit_price_guard_block`, real `entry_submit_revalidation_block`, stale/passive-probe 차단만 남긴다. `dynamic_entry_price_resolver`는 `latency_pass`, `order_leg_request`, `order_bundle_submitted`, `entry_ai_price_canary_*`, `entry_submit_revalidation_warning`, `scalp_sim_entry_*`, `scalp_sim_buy_order_*`를 소비해 `bid-1`, `bid-2`, `bid-3`, `best_bid`, `AI_candidate`, `reference_target`, `timeout_15s`, `timeout_30s` 후보별 `fill_rate`, `full_fill_rate`, `partial_fill_rate`, `cancel_rate`, `late_fill_rate`, `missed_upside`, `source_quality_adjusted_ev_pct`를 비교한다. `AI_candidate`는 `candidate_failure_count/rate`와 `failure_reasons`로 `missing_snapshot`, `invalid_price`, `pre_submit_price_guard`, `above_best_ask`, `skip_low_confidence`를 별도 집계한다. `entry_price_execution_quality`는 real broker result, cancel, late-fill, partial/full fill join을 real-only audit으로 분리한다. sim pre-submit guard verdict는 `liquidity_pre_submit_guard_p1`과 `overbought_pullback_guard_p1` family의 source-only 표본으로 남기고, 가상체결을 중단하지 않는 counterfactual bucket으로만 사용한다. `candidate_failure_count`, `unpriced_or_stale_warning_count`, `excluded_from_fill_ev_count`는 정상 telemetry일 수 있으므로 단독 workorder trigger가 아니며, `report_contract_gap` 또는 명시적 failed/missing/incomplete contract status가 있을 때만 source-quality/report instrumentation workorder로 라우팅한다. `passive_probe` 제출 직전 revalidation에서 `stale_context_or_quote`가 확인되면 브로커 제출 전 `entry_submit_revalidation_block`으로 차단하고, simulator에서는 `scalp_sim_entry_submit_revalidation_block`으로 `dynamic_entry_price_resolver` 관찰 표본만 남기며 모두 `actual_order_submitted=false`를 유지한다.

Swing micro source-quality는 `swing_micro_ws_quote_source=missing`을 micro 계산 결손과 분리해 `provenance_gap_count`로 보고한다. `orderbook_micro_reason=ready`와 `insufficient_samples`는 readiness metric으로 분해하고, spread `>10`은 `wide_spread_count/rate/max_spread_ticks`로 노출하되 hard block이 아니라 `source_quality_adjusted_ev_pct` 감점 또는 필터 후보로만 사용한다. 이 metric들은 swing real order enable, threshold mutation, provider route, bot restart 근거가 아니다.

`scalp_sim_ai_budget_manager` family는 확대된 `scalp_ai_buy_all` holding 표본에서 OpenAI 호출 폭증을 제어하는 sim-only 운영 owner다. runtime event는 `scalp_sim_ai_holding_live_call`, `scalp_sim_ai_holding_reuse`, `scalp_sim_ai_holding_deferred`, `sim_ai_budget_exhausted`, `sim_ai_critical_bypass`이며 모두 `actual_order_submitted=false`, `broker_order_forbidden=true`, `decision_authority=sim_observation_only`를 남긴다. 별도 장후 deferred-review producer는 downstream 소비자가 없어 2026-08-01 폐기했다. deferred/reuse/call runtime event 자체는 기존 budget-manager attribution source로 유지한다. 이 family는 provider route, BUY/submit threshold, broker/order guard, real holding 판단을 변경할 수 없다.

`scale_in_split_order_plan` postclose producer는 pipeline/threshold JSONL을 `streaming_relevant_field_projection`으로 읽고 AVG_DOWN identity/anchor, observed price, terminal join에 필요한 필드만 보존한다. `input_summary.source_read_contract`는 원본/보존 event 수와 `full_source_materialized=false`를 기록한다. 이 메모리 경계는 기존 counterfactual selector와 수량·가격 policy owner를 바꾸지 않는다.

## 5. 금지선

- 누적 평균 단독으로 live threshold를 적용하지 않는다.
- report-only 산출물 이름에 `apply_ready=True`가 있어도 `auto_bounded_live`의 deterministic/AI/same-stage owner guard를 통과하기 전에는 runtime 변경으로 해석하지 않는다.
- 장중 threshold runtime mutation은 열지 않는다. 적용 단위는 장후 산출 -> 다음 장전 apply plan -> 장후 attribution이다.
- Project/Calendar owner가 없는 미래 자동화 작업은 유효한 next action으로 보지 않는다.
- Sentinel abnormal alert를 즉시 threshold 완화/강화, fallback 재개, 자동 매도, cache TTL mutation, bot restart로 연결하지 않는다.
- postclose collector가 live `pipeline_events_YYYY-MM-DD.jsonl` 대신 immutable snapshot을 읽어 `checkpoint_completed=true`를 만들더라도, 이는 R0/R1 수집 안정화일 뿐 auto bounded apply 통과로 보지 않는다.
- IPO listing-day autorun status는 YAML-gated 실주문 실행 감사용이다. 결과를 threshold-cycle calibration, daily EV, scalping/swing runtime threshold 입력으로 자동 소비하지 않는다.
- `runtime_approval_summary`는 read-only 요약 artifact다. `runtime_mutation_allowed=false`일 때는 flow 조정, 주문 차단, threshold mutation 권한이 없다.
- 같은 날짜 workorder 재생성 여부를 `mtime`만으로 판정하지 않는다. `generation_id/source_hash/lineage` diff가 source of truth다.
- `update_kospi_status.completed_with_warnings`는 DB 적재 실패와 동일하지 않다. `failed_steps`를 확인해 `recommend_daily_v2`, swing daily reports 같은 후행 step 실패를 분리한다. Legacy dashboard DB upload step은 제거됐고 파일/Parquet/DuckDB가 canonical source다.
- `_error.log` 파일명만 보고 모든 `DB` 문자열을 DB 장애로 분류하지 않는다. `log_scanner`는 ERROR/CRITICAL/traceback/exception/에러/오류/실패 후보 라인만 incident 후보로 본다. `MEMORY_ERROR`는 실제 memory/OOM signature만 인정하고 `kiwoom_*` logger 이름 내부의 `oom` 같은 부분 문자열은 메모리 장애로 분류하지 않는다.
- `win_rate`, `simple_sum_profit_pct`, `active_unrealized`, `combined_diagnostic`, `counterfactual_only` 지표는 단독으로 runtime apply, 실주문 전환, threshold 완화/강화 승인 근거가 될 수 없다.
- `metric_role`, `decision_authority`, `window_policy`가 없는 새 관찰지표는 threshold candidate가 아니라 instrumentation/source-quality backlog로만 본다.
