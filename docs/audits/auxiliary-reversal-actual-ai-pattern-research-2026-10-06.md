# 상승반전 지점의 보조 AI 실제 호출 연구 — 2026-10-06

## 1. 수행 범위와 결과의 의미

**새로 찾은 가격 반전 지점 118개에 OpenAI `gpt-5.4-nano`를 실제 390회 호출했다.** A/B/C를 각 118회, 후속 D를 같은 지점 중 36개에 추가 호출했다. 50종목·8거래일·프리/정규/애프터가 포함된다. 모든 요청·원문 응답·response ID·토큰·입력/프롬프트 해시를 보존했다.

입력은 기존 기계판정 행에서 고르지 않았다. 앞선 연속 가격 반전 연구의 확정된 승리·실패 지점에서 날짜/시장/유형별 해시 순으로 추출했다. 승리와 실패 중 어느 쪽인지는 선택에 사용하지 않았으며, 미확정 가격 경로만 제외했다. 가격 연구에서 선택한 유형별 후보 중심 96개와 모든 반전에서 추출한 비교점 24개를 합쳐 중복 2개를 제거했다.

**선택된 118개 중 승리 85개·실패 33개다.** AI에는 결과·후행 가격·목표 도달 시각·누적 승률을 전혀 주지 않았다. 입력은 해당 반전 시점까지의 체결·호가·낙폭·반등폭·수량·과거 VWAP와 단기 가격 변화뿐이다. 저점 매수를 가정하지 않고 첫 상승 당시 매도호가를 진입 기준으로 한다.

승리는 비용 후 +0.4%를 30분 안에 먼저 도달한 경우다. 비용 후 소프트손절 −3.0% 선도달 또는 온전한 30분 목표 미도달은 실패다. 비용률 0.23%와 원래 경로 라벨을 그대로 사용했다. 손익액·EV·손익비·최소 표본 수를 채택 문턱으로 추가하지 않았다.

이번 비율은 **118개 연구 표본의 실제 AI 응답 결과**다. 149만여 반전 전체를 AI에 호출한 결과나 독립 거래 실적이 아니다. 날짜·유형별 표본 추출 비중이 원래 모집단과 다르고 반복 반전이 남아 있으므로 전체 승률 추정치로 일반화하지 않는다. 각 지점·후보는 한 번씩 호출했으며 반복 호출에 따른 응답 변동성은 측정하지 않았다.

**우선 연구할 패턴은 “첫 상승은 나왔지만 매수수량 비중과 VWAP는 아직 약한 반전 초기”다.** 두 특징을 동시에 만족한 지점은 27개(승리 22·실패 5)였다. A는 전부 미통과였고, C는 승리 15개·실패 2개를 PASS하여 승리 PASS율 68.2%, PASS 승률 88.2%였다. 삼성 정규는 PASS 3/3승, 비삼성 프리 3/3승·정규 6/8승·애프터 3/3승이다. 삼성 프리/애프터는 이 교집합 표본이 없었다. 이는 결과를 본 뒤 발견한 표본 내 패턴이며 독립 검증이나 종목 전체 보장으로 쓰지 않는다.

반면 두 특징 중 하나만 있으면 모두 같은 효과라고 확대할 수 없다. 합집합 76개에서 C는 33/43승(76.7%)이었다. 음의 단기 모멘텀이나 수량 미증가까지 일괄 중립화한 전체 C의 69.3%도 함께 남긴다.

## 8. 보완 방향

실제 응답 전환 사례로 삼성전자 9/30 09:05:25(매도호가 273,500원, 목표 도달까지 3.58분)와 비삼성 028260의 10/6 09:14:38(매도호가 345,500원, 8.09분)이 A의 VETO에서 C의 PASS로 바뀌었다. 모두 AI에 후행 결과를 주지 않은 동일 지점 비교다. 이 사례는 승리 회복을 설명하기 위한 것이며 실패 PASS도 위 분모에 포함했다.

1. **반전 확인 소유를 명확히 한다.** 기계가 원시 가격의 하락→첫 상승을 확인했다면 그 사실을 보조 입력의 명시적 setup/trigger로 전달한다. 보조가 기존 추세 확인을 처음부터 반복하도록 만들지 않는다.
2. **직전 약세와 현재 반전 무효화를 구분한다.** 매도 우세·음의 모멘텀·VWAP 아래 가격·수량 미증가를 삭제하지 않는다. 실제 수치를 전달하되, 상승반전 가설에서 자동 거부 사유가 되는지는 시장·유형별 PASS 승률로 판단한다.
3. **일괄 완화 대신 실제 개선된 유형을 우선한다.** 승리 PASS 증가와 PASS 표본 승률을 동시에 표에 공개한다. 실패 통과만 커진 유형에 C를 복사하지 않는다. 보조 연구는 AI가 실제 선택한 PASS를 기준으로 비교한다.
4. **응답 모순을 따로 고친다.** CAUTION인데 NO_BLOCKING_RISK를 쓰거나 근거 없는 SOURCE_QUALITY_GAP을 출력한 사례를 PASS로 자동 변환하지 않는다. 사실 역할·응답 schema·인용 규칙을 단순하게 맞춘 후 실제 응답으로 다시 확인할 대상이다.
5. **장후 학습 원천은 가격 반전 전체 목록으로 둔다.** 기계가 과거 ENTER_NOW를 찍어 AI를 호출했던 행만 누적하면 이번에 찾은 승리 지점이 다시 사라진다. 반전 시각의 입력 스냅샷, 후행 승패 라벨, 실제 AI 응답을 분리 저장하고 같은 지점에서 비교한다.

## 9. 검증·권한·재현

리뷰에서 문맥 사실과 active 위험이 같은 코드일 때 인용 목록을 덮어쓰는 검증기를 합집합으로 수정했고, 모델 원응답 PASS와 인용 검증 통과를 분리했다. 원문 응답은 수정하지 않았다. 11개 회귀에서 미래정보 배제·시점 접두 불변성·수치 보존·표본 선택의 승패 독립성·검증 기준 분리를 확인한다. 상세 실행 결과와 해시는 최종 검증 파일에 남긴다.

입력 662,276토큰·출력 34,422토큰, 고유 response ID 390개를 확인했다. 실제 호출은 기존 offline OpenAI executor와 공용 provider budget ledger를 사용했다. `store=false`, HTTP, `gpt-5.4-nano`, reasoning `none`, 요청당 최대 출력 512토큰이다. 모델/운영 provider 설정은 변경하지 않았다. ledger의 0 비용은 기존 operator accounting 값이며 실제 청구금액 0이라는 주장이 아니다. 공용 오프라인 ledger는 이번 390회로 당일 한도에 도달했고 잔여 호출은 0회다. 같은 장부를 쓰는 후속 오프라인 호출은 당일 예산 제한을 받는다. live entry 호출 한도와는 별개다.

운영 프롬프트·정책·봇·주문·장후 wrapper를 변경하지 않았다. 기존 전체 live schema/validator의 호환성 및 주문 성과는 이번 연구의 검증 범위가 아니다. 새로운 사실 역할을 운영에 옮기려면 입력 producer·prompt·validator를 같은 계약으로 수정하는 별도 구현이 필요하다.
