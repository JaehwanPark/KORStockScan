# 관측 기계 후보 생성기 연결·재생성 결과

## 1. 결정

- 실제 장후 진입점 `build_machine_policy_report`에 명시적 관측 요청 경로를 구현했다. 기존 native 경로는 기본 경로로 남고, 관측 군집을 native opportunity로 바꾸지 않는다.
- 비삼성 `pullback_p60_v0`는 **관측 계약에서 학습 선정 및 후단 비교를 통과**했다. 삼성전자 `absorption_p60_v10`는 학습 선정 후 후단의 기존 정책 승률 미산정 때문에 우월 판정을 보류했다.
- 이 결과는 운영 정책 발행·적용이 아니다. `policy_by_scope={}`, `promotion_pass=false`, `allowed_runtime_apply=false`; 새 스키마를 기존 운영 activation이 거부하는 회귀를 포함했다. 비용 반영 가격 CF도 실제 수익과 구분한다.
- 비교 날짜 10/2는 이전 연구에서 반복 소비했다. 독립 holdout 또는 일반화 성능 확보로 표시하지 않는다.

계획: [관측 평가 계약](../proposals/machine-observation-generator-contract-plan-2026-10-04.md). 현재 소유 항목: [10/4 체크리스트](../checklists/2026-10-04-stage2-todo-checklist.md) `MachineObservationGenerator1004`.

## 2. 구현과 원천

소유 모듈은 `src/engine/scalping/entry_observation_recipe_policy.py`, 회귀는 `src/tests/test_entry_observation_recipe_policy.py`다. 다음을 구현했다.

1. 삼성/비삼성 두 고정 표현식의 정확한 scope·parent·kernel hash·교체형·관측 권한 검증. 기존 scalar 임계치나 `micro_confirmation_recipe` 값을 다른 의미로 재사용하지 않았다.
2. 32개 원천/연구 파일 hash를 재생 전후 대조. 원 capture로 실제 평가 함수를 다시 호출하고 parent 행동을 대조했다. 모든 7,069건(비삼성6,550·삼성519)이 일치했고 원천 제외는 0건이다.
3. 승격 ID 없는 probe도 source·raw hash·시각·원 비용 계약이 유효하면 평가한다. 원 native identity는 그대로 보관한다. 새 native ID를 만들지 않았다.
4. 원 ask·동일 관측 시각·전비용·60분 경로를 결속했다. 삼성 과거 라벨의 첫 부분봉 도달을 순서 미확정으로 보완했다. 미확정 진입도 최대 점유기간을 소비하며 다음 성공 관측으로 바꾸지 않는다.
5. 종목×날짜×venue/session 내 경계확정 승률을 계산한 뒤 군집을 동일 가중한다. 반복 관측은 군집 N을 늘리지 않는다. 군집 간 독립성은 입증하지 않았다. 생성기의 기존 raw/지원조정 승률 함수를 이 N에 적용한다.
6. 학습 선정은 후단 비교 전 고정한다. 성공100%/80% 보존율과 미확정 기존 ENTER 변경 수는 탈락 조건이 아니다. 기존 선택의 경계결과가 전혀 없는 경우에만 기존 승률을 0으로 대입하지 않고 비교 불가를 표시한다.

삼성의 저장되지 않은 최신 snapshot 전체 feature 입력을 복원하지 않았다. 원 capture와 독립 archive receipt의 기존 보관 증거를 사용했다. 보조 AI·새 원천·API/provider·주문을 소비하거나 실행하지 않았다.

## 3. 비삼성 선정 결과

아래 **주승률은 군집 동일 가중**이다. 관측 단순 비율과 분모가 다르다.

| 구간 | 기존 → 후보 주승률 | 기존 → 후보 경계확정 군집 N | 기존 → 후보 지원조정 점수 |
|---|---:|---:|---:|
| 학습 9/29·9/30 | 42.59% → **68.45%** | 68 → 55 | 33.20 → 57.49 |
| 후단 비교 10/2 | 55.56% → **71.43%** | 27 → 28 | 40.04 → 56.00 |

- 날짜별 주승률: 9/29 **46.25→63.93%**, 9/30 **37.04→75.23%**, 10/2 **55.56→71.43%**.
- 10/2 후보 선택49관측: 목표22·손절10·시간종료3·첫 부분봉5·비용 결손3·후속 부족6. 경계확정32관측의 단순 승률은 **68.75%**로 이전 결과와 같다. 기존은 목표20·손절13, 단순60.61%다.
- 9/30 후보50관측과10/2 후보49관측은 모두 원 capture의 `source_event_stage=zero_base_probe_machine_only_v1`이다. 이번에는 승격 ID 부재로 학습을 제외하지 않았다. source route와 source event stage는 별도 필드로 대사했다.
- 해당 비교에서 유효 종료 가격 CF 평균은 기존 **-0.3230%**, 후보 **-0.2672%**다. 개선됐지만 음수다. 목표 +0.1%와 손절 -0.7%-비용의 비대칭이며 운영의 실제 trailing/청산·수익으로 해석하지 않는다.
- 결과: `selected_on_train` 및 `selected_observation_recipe` 모두 비삼성 고정 표현식, `observational_candidate_supported=true`.

## 5. 9/29 반복·선택 시각 민감도

비삼성에서 사전600초 축소 후 군집 주승률은 **기존59.62%→후보56.04%**로 뒤집힌다. 원 전체 관측의 개선만으로 빈도에 강건하다고 판단할 수 없다.

- 축소 시54종목의 선택 관측이 변했다.
- 후보: 공통 선택34건, 빠진 관측은 목표38·손절21·첫 부분봉11, 새 선택은 목표5·손절4·첫 부분봉2·후속 부족1이다. 축소 후 확정 목표17·손절11이다.
- 기존: 공통 선택37건, 빠진 관측은 목표32·손절32 등, 새 선택은 목표1·손절1이다. 축소 후 확정 목표18·손절12다.
- `000990`은 후보 목표6·손절3에서 축소 후 손절1만 남는다. `353200`은 목표5·손절2에서 목표2·손절1로 바뀐다. 이 값들은 수정할 threshold를 고르기 위한 근거가 아니라 어떤 시점이 없어졌는지 설명하는 진단이다.
- 이전 600초 진단은 request code·원 bundle별로 시계를 재시작했다. 이번 주단위는 종목·날짜·venue/session으로 제한한다. 이전 방식도 별도로 재현했으며 기존 목표20·손절12(62.50%), 후보17·11(60.71%)로 이전 결과와 일치한다. 새 방식의 기존18·12(60.00%)와 분모를 혼동하지 않는다.
- 삼성도 10/2 사전600초 축소 시 후보 경계 승률이0%로 변한다. 반복 관측을 줄인 조건에서 안정적인 삼성 신호를 확보했다는 결론은 내리지 않는다.

## 6. 리뷰·보완·검증

리뷰에서 다음을 보완했다.

- 삼성 첫 부분봉 도달의 과거 라벨을 확정 승리/손실로 소비하지 않도록 보완.
- 요청의 표현식 group과 적용 group 결속, archive hash가 원천 manifest에 실제 포함됐는지 검증.
- 60분 요청 종료시각과 세션종료 대조, timeout의 세션 경계 확인.
- 식별 가능한 중복 capture/경로/receipt는 해당 ID로 국소화; 중복 한 건으로 다른 종목 전부를 버리지 않는다.
- kernel manifest에 stream loader·native provenance 파서를 포함. v1 코드와 driver는 hash 일치 보관본으로 보존하고 수정본은 새 `run-v2`로 생성했다.
- 민감도 부록의 probe 분류가 `zero_base_route`를 잘못 비교하던 부분을 원 capture의 `source_event_stage`로 수정했다. 수정 전 부록은 보존하고 `sensitivity-reviewed.json`에 supersedes hash를 기록했다. 선택 결과와 모든 승률·민감도 수치가 같음을 대조했다.

표적 회귀 **159 passed**: 원 위험 guard, 빈 native ID의 관측 선정, 반복 군집 N, 결손 진입 점유, 과거 성공 제거 허용, 학습/후단 분리, cost/ask/시각/hash/scope 결속, 기본 생성기 회귀, 운영 activation 거부. compile·diff·25개 문서 link/단일 owner·print-only parser도 통과했다. 재생 v1/v2의 모든 학습·후단·날짜·600초 지표가 동일하며 최종 실제 생성 시간은171.94초다. 검토한 범위의 미해결 구현 결함은0건이고 빈도 민감도·음수 CF·독립 날짜 부족은 별도 연구 한계다. 전면 거래 suite·운영 장후 일괄 자동화·배포/PID 검증은 이번 격리 코드 범위 밖이므로 실행하지 않았다.

## 7. 근거와 다음 작업

- 최종 격리 산출물: `tmp/machine-observation-generator-20261004/run-v2/{request,report,execution,sensitivity-reviewed,validation}.json`.

**비삼성은 후보 자체를 잃지 않고 다음 단계로 넘길 수 있다.** 다음 검증은 이미 고정한 후보의 관측 시각 의존성을 사건 단위로 분해하고, 실제 운영 종료 계약을 붙여 비용 후 결과를 확인하는 것이다. 이번 음수 가격 CF를 승률 개선으로 가려서는 안 된다. 삼성은 같은 고정 신호에서 기존/후보 모두 정의되는 시간종료 포함 결과를 별도 목표로 명시해 비교하는 편이 유효하다. 이미 사용한 날짜로 새 독립 검증을 만들었다고 표현하지 않는다.
