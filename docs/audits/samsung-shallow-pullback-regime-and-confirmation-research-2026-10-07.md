# 삼성 상승 흐름·얕은 눌림 후속 연구 결과

## 1. 결론

**기계판정 구현 검토에 올릴 새로운 삼성 상승 구간 후보를 확보했다.** 현행 정규장 단일 `DD5_GE_1_2`는 이번 원천의 상승 구간에서 매칭 0이었다. 기존 확정 승리 13건은 모두 세션 첫 관측가격 대비 하락 구간이었다. 따라서 큰 낙폭 반전과 상승 중 작은 눌림을 구분해 정책 후보를 선택할 필요가 있다.

이번 선호 후보는 **세션 상승 + 최근 60초 상승 + 최근 저점 상승 → 5분 낙폭 0.4~0.8%의 첫 반전 → 원 저점을 재접촉하기 전에 5초 내 다음 상승 확인**이다. 과거 31/31·오늘 3/3, 미확정 19건이며, 확인 진입 중복을 제거하면 누적 32/32·미확정 18건이다. 표본을 이유로 탈락시키거나 기존 성공 보존 조건을 적용하지 않았다. 100%는 이번 관측의 raw 비율이며 미래 성과 또는 broker PnL 보장은 아니다. 오늘 3개는 서로 다른 확인 시점이나 **같은 한 번의 목표 도달 시각**에 모인다.

5분 낙폭이 0.4%보다 작은 유형에서는 다른 후보가 우세했다. 고점·저점 동반 상승에서 더 높은 재눌림 저점을 확인하는 후보는 과거 76/131(58.0%), 오늘 6개 확정 승리·110개 미확정이다. 두 유형을 합친 raw 결과는 과거 107/162(66.0%)이고 서로 다른 확인 시점으로 세면 105/160(65.6%)다. 이를 첫 유형의 100%와 혼합하지 않는다.

운영 코드·정책 발행·selector·배포·재기동·주문은 변경하지 않았다. 현재 단일 rule 생성기와 kernel에는 새 흐름별 분기·pending 확인 계약을 구현해야 한다.

## 2. 실행 범위와 원천

사용자 요청은 “삼성 추가 연구를 이어가자”다. [실행 계획](../proposals/samsung-shallow-pullback-regime-and-confirmation-research-plan-2026-10-07.md)에 따라 삼성 기계판정에 집중했다. AI 응답/판정은 입력·라벨·선택에 사용하지 않았다.

- 원천: 검토된 SOR 정규장 9/21·22·23·28·29·30·10/2·10/6의 삼성 normalized 틱과 반전, 오늘 기존 파일의 고정 바이트 접두.
- 오늘 종료: **09:55:48.565 KST**, 65,163개 틱·15,794개 첫 반전. 앞선 09:39 연구 접두/결과는 보존했다.
- 비용 0.23%, 실제 확인 시점의 매도호가 진입 기준, 진입 후 30분 내 비용 후 +0.4%/soft -3% 선도달.
- 같은 source item의 기존 완성 분봉만 라벨 보완에 사용했다. 오늘 동결 종료 시각 이후 분봉은 제외했다. 새 API/provider 호출은 0이다.
- 미성숙·원천 단절·quote 결손은 UNRESOLVED다. 확인 없음과 진입 후 실패를 구분했다.
- 세션 기준값은 **공식 시가가 아닌 최초 정상 관측가격**이다. 9/23 원천은 09:27부터 시작하므로 당일 공식 시가로 해석하지 않는다. 오늘 기준은 09:00:10.217의 269,500이다.

## 3. 흐름별 차이

구분기는 최초 반전 시각에 고정했다. 후행 상승/종가를 분류에 넣지 않았다. 아래는 삼성 자체 가격 흐름이며 외부 지수의 상승장/하락장 분류가 아니다.

| 흐름 구분 | 상승 조건 | 해당 상승 구간 전체 첫 반전의 과거 승률 | 기존 1.2% 후보 |
| --- | --- | ---: | --- |
| 직전 60초 변화 | ≥+0.2% | 3,191/8,609, 37.1% | 매칭 0 |
| 최초 세션 관측가 대비 | ≥+0.4% | 15,892/57,359, 27.7% | 매칭 0 |
| 두 30초 구간 구조 | 고점·저점 모두 상승 | 2,129/7,242, 29.4% | 매칭 0 |

기존 DD5 ≥1.2% 원천은 총 480개, 승리 13개·미확정 467개다. 13개 승리는 10/6의 두 목표 도달 시각이며 전부 세션 DOWN이다. 상승 중 눌림 후보와 다른 유형이었다. 상승 구간의 기존 후보 매칭 0을 승률 0%로 바꾸지 않았다.

이전 연구의 “작은 낙폭 + 직전 60초 상승 ≥0.2%”는 37.1%였다. 여기에 **첫 세션 관측가 대비 +0.4% 이상**을 추가한 즉시 진입 후보는 과거 **2,277/4,830(47.1%)**다. 즉 기존 원천 안의 흐름 구분이 의미 있는 후보 차이를 만들었다. 다만 날짜별로 9/29 59.0%, 9/30 0%, 10/2 9.9%로 차이가 있었다.

## 4. 확인을 기다리는 효과 분리

최대 낙폭 ≤0.4% 모집단에서 10개 선행 필터 × 7개 확인 방식을 비교했다. 전체/세 구분기별 UP·FLAT·DOWN·UNKNOWN 통계 596개를 남겼다. 추가로 같은 70개 조합을 상승 구간의 기존 낙폭 경계별로 나눠 532개 통계를 만들었다. 추가 분리는 사후 탐색이며 독립 검증 연구로 부르지 않는다.

| 같은 반전에서 양쪽 결과가 확정된 비교 | 첫 진입 승리 | 확인 진입 승리 | 비교 수 |
| --- | ---: | ---: | ---: |
| 무필터 다음 상승 확인 5초 | 1,993 | 1,980 | 8,293 |
| 무필터 더 높은 재눌림 15초 | 1,736 | 1,715 | 6,717 |
| 60초 UP·DD5 0.4~0.8·다음 상승 5초 | 45 | 43 | 51 |

**대기 자체의 진입 가격 효과는 개선을 입증하지 못했다.** 확인 후보의 raw 승률이 높아진 것은 많은 원 반전에서 진입하지 않은 선별 효과였다. 가격·30분 시계를 첫 진입 그대로 두면 이 구분을 놓친다.

예컨대 60초 UP·DD5 0.4~0.8·다음 상승 5초는 원 반전 1,216개 중 83개에서만 진입이 확인됐다. 원 저점 재접촉 1,128개·정상 timeout 4개·경로 검열 1개는 진입하지 않았다. 미진입 중 원 첫 진입 WIN도 382개 있었다. 첫 성공을 100% 보존하는 조건은 사용하지 않았다.

## 5. 선호 후보: 상승 흐름의 0.4~0.8% 눌림

### 5.1 계산 조건

최초 반전에서 다음을 동결한다.

1. 직전 하락 구간 낙폭 ≤0.4%.
2. 세션 첫 정상 관측가격 대비 ≥+0.4%.
3. 정상 연속 관측의 직전 60초 수익률 ≥+0.2%.
4. 최근 30초 저점이 그 이전 30초 저점보다 높음.
5. 최초 상승 직전 관측 5분 고점 대비 저점 낙폭 0.4~0.8%.

그 뒤 원 저점에 다시 닿기 전에 5초 안에 최초 상승 가격보다 높은 체결 가격을 관측하면, 그 시점의 정상 매도호가를 진입가로 사용한다. 원 저점 재접촉·native path 단절·시간 만료는 각각 분리한다. 미래 결과를 보고 첫 반전 시점에 매수한 것으로 계산하지 않는다.

동일 선행 필터에서 첫 상승 즉시 진입하면 과거 **323/331(97.6%)**·미확정 144개, 오늘 6/6이었다. 확인을 기다린 후보는 과거 31/31·미확정 19개, 오늘 3/3이다. raw 승률 우선 순위에서는 확인 후보가 앞서지만 더 많은 기회를 잡았다고 설명하지 않는다. 확인 미성립으로 빠진 원 첫 승리 295개도 공개한다.

실제 사례:

- 최초 반전 09:02:04.518: 저점 270,500, 최초 매도호가 271,000, 직전 하락폭 0.3683%, 5분 낙폭 0.5515%.
- 당시 60초 변화 +0.8372%, 세션 기준 대비 +0.5566%, 최근 저점 상승.
- 다음 상승 확인 09:02:04.644, 매도호가 271,000에서 새 진입 기준 확정.
- 비용 후 +0.4% 필요 가격 약 272,711원, 정상 가격 목표 도달 09:02:54.519, 확인 후 49.875초.

현재 1.2% 규칙은 이 사례를 선택하지 않는다. 새 후보 조건은 이 사례를 선택한다. 이는 normalized 가격·quote를 통한 반사실 결과이며 실제 주문 수량별 체결/PnL은 아니다.

## 6. 더 작은 낙폭과 결합 후보

DD5 <0.4%에서는 세션 상승·60초 상승·고점/저점 동반 상승에 원 저점보다 높은 재눌림 후 상승을 15초 안에 확인하는 후보가 해당 탐색 중 우세했다.

- 과거: 76/131(58.0%), 미확정 37개.
- 오늘: 확인 진입 116개 중 승리 6개·미확정 110개.
- 누적: 82/137(59.9%), 미확정 147개.
- 날짜별: 9/29 76/106, 9/30 0/3, 10/2 0/22. 날짜에 따라 차이가 컸다.

5절 후보와 결합하면 과거 107/162(66.0%), 오늘 9개 승리·110개 미확정이며 누적 116/171(67.8%)다. 서로 다른 확인 시점으로 세면 과거 105/160(65.6%), 누적 114/169(67.5%)다. 오늘 확정 승리만으로 나머지 110개의 결과를 추정하지 않았다.

이 결합 후보를 기존 전체 후보 13/13보다 높은 승률로 표현하지 않는다. 목적은 기존 후보가 매칭되지 않은 상승 구간을 분리해 새 후보를 만드는 것이다. 가장 작은 낙폭을 모두 같은 규칙으로 승인할 근거는 아직 확보되지 않았다.

## 7. 실제 Main 소비와 구현 과제

오늘 동결 종료까지 삼성 정규장 Main 기계 관측은 BLOCK 23·RECHECK 2·ENTER_NOW 0·SOURCE_INVALID 0이었다. 그중 native 반전 event를 정규 가격 원천에 연결한 6건에서는 선행 broad 상승 필터가 매칭되지 않았다. 전수 가격 반전 15,794개와 Main 평가 25개는 서로 다른 모집단이다. 오늘 원천에서 확인한 신규 패턴의 시각에 Main이 실제 평가했다고 처리하지 않는다.

다음 구현의 핵심:

1. **상승 구간 분기:** 삼성 정규장 단일 최고 rule과 상승 중 작은 눌림의 별도 분기를 설계한다. raw 승률 순위를 유지하고 기존 성공 보존·추가 economic/holdout 문턱을 넣지 않는다.
2. **동일 특징 생산:** same item/route/day 기준 첫 세션 관측가격, 정확한 두 30초 구간, 60초 변화·정상 연속성을 runtime/postclose가 같은 코드로 계산한다. 관측 시작가격과 transport epoch 복원을 구분한다.
3. **확인 상태 계약:** 최초 반전 ID·동결 분기·원 저점·시계·만료 사유를 유지하고 확인 틱의 새 source ID/매도호가로 평가를 시작한다. 여러 anchor의 같은 확인 시점은 중복 진입하지 않는다. 원 저점 재접촉과 재연결을 현재 값으로 성공 처리하지 않는다.
4. **Main 전달:** 후보 발생과 Main 판정 소비 간의 freshness·평가 지연을 검증한다. WS callback에서 직접 주문/AI 호출하는 방식은 사용하지 않는다. 기존 Main admission·평가·hard source/order/account/capital/custody guard 안에 전달한다.
5. **생성기 parity:** 같은 동결 원천에서 새 후보 rank·분기 payload·runtime 접두가 이번 확인 시점/가격을 재현하는지 검증한다. 연구 artifact를 정식 runtime policy 파일로 복사하지 않는다.

이번에 raw 100%를 확보한 조건부 후보를 구현 우선 후보로 제시한다. DD5 <0.4%의 별도 후보와 결합 연구는 다른 raw 성과를 가진 보조 연구 결과로 남긴다. 현재 운영 수용 또는 실주문 성능 검증 완료라는 뜻은 아니다.

## 8. 리뷰·검증

`korstockscan-review-gate`로 계산·원천·보고서를 검토했다. 시간 구간을 과거 마지막 틱의 시각으로 이동시키던 초기 구현을 수정하고 정확한 `[t−60,t−30)`·`[t−30,t]`로 재계산했다. 빈 구간 UNKNOWN, 확인 시점 중복, paired 비교와 미진입 WIN 공개를 보완했다.

- 의미 있는 표적 pytest 14 PASS: 시간 경계·빈 구간·접두 불변성·원 저점 재접촉·미래 이후 재접촉·higher low·경로 단절·이미 회복된 고점·새 진입가격/30분 재시작·미확인/실패 분리·낙폭 분류 경계·후행 label과 branch 분리.
- 과거 8일 356,455개 첫 반전의 기존 라벨과 재계산 라벨 차이 **0건**.
- 원천/event SHA·같은 source item 분봉 동결·분모 보존·오늘 원천 접두 불변성을 확인했다.
- compile·문서 링크/authority·print-only backlog parser·git diff whitespace 검증.
- live 거래 suite, 실제 API/provider, 정식 장후 재생성, 정책 배포·PID·체결/PnL 검증은 실행하지 않았다.
