# 삼성전자 연속 tick 압력 전환 연구 실행·검증

작성일: 2026-10-05 KST. 사용자 `계획 실행`에 따라 [계획](../proposals/samsung-continuous-tick-window-transition-research-plan-2026-10-05.md)의 R0–R4를 실행했다. 기존 9/29·9/30·10/2 원천만 소비했다. 신규 수집·API·주문·운영 정책 발행·배포·재기동은 실행하지 않았다.

## 1. 결정

**`absorption_p60_tick_shift1_v1` 한 개를 이후 날짜 검증 후보로 동결했다.** 연구 권고 범위는 전체 origin이며, 상시감시 전용 개선은 확인하지 못했다. 비중복 직전10tick 후보는 기존 흡수 후보보다 나빠 종료했다. 두 가설의 계산은 끝났으며 임계값·기간·유형 조합을 추가하지 않는다.

새 후보는 원흡수 ENTER에서 현재10tick의 매수압력이60 이상이고, 한 tick 앞선10tick의 압력이60 미만일 때 ENTER를 유지한다. 알려진 조건 실패는 RECHECK, 추가 조건 미확정은 원흡수 행동 승계다. 원흡수 BLOCK/RECHECK와 원 hard/source guard를 보존한다. 가격 상승·손절 결과를 입력으로 사용하지 않는다.

## 2. R0–R1: 이미 가진 체결자료의 소비 범위

기존 원천35개 SHA가 모두 일치했다. 원흡수·H2 frozen, 추가 의존 코드·archive 생산 계약을 포함한 최종54개 원천/코드 SHA를 읽기 전후 검증했다. 전체519·상시감시206관측의 원 identity/raw/행동/label을 보존했다. 기준 정책·원흡수·H2의 기존 선택 ID와 지표도 재현했다.

보관 체결의 `t`는 `local_receive_timestamp`, `ex`는 `exchange_timestamp`다. 해당 의미와 `005930_AL/SOR/SOR_REGULAR` 필터는 기존 정규화 생산 코드 및 봉인된 manifest로 확인했다. archive 수신시각·sequence·epoch의 원 의미를 보존했으며 Main transport epoch와 동일한 것으로 치환하지 않았다.

| 조건 식별 가능 관측 | 기존 H2 | 1틱 이동 | 비중복 직전10틱 |
|---|---:|---:|---:|
| 전체519 | 43 | 430 | 429 |
| 상시감시206 | 0 | 204 | 204 |
| 원흡수 ENTER59 | 4 | 59 | 59 |

따라서 이번 두 가설에 필요한 자료 대부분은 이미 있었다. 판정 capture 간격을 비교하던 방식이 상시감시 체결의 세부 변화를 충분히 사용하지 못했다. 식별률 개선 자체는 수익 개선과 구분한다.

전체 조건의 참/거짓/미확정은 1틱 이동 **21/409/89**, 비중복10틱 **92/337/90**이다. 원흡수 ENTER에서 실제 유지되는 신호는 각각 **6/59**, **26/59**다.

결손은 1틱 이동에서 기존 current receipt 불일치89건, 비중복에서 같은89건과 직전 endpoint 5초 초과1건이다. 상시감시의 남은2건은10/2의 원 feature와 archive10tick 재계산 불일치다. 두 경우 모두10tick·시각·연속성은 있지만 매수압력이 각각 원39.19/47.48과 archive31.71/27.49로 다르다. 원본 값을 새 값으로 고치지 않고 미확정으로 유지했다. 두 행의 원흡수 행동은 모두 RECHECK다.

## 3. R2–R3: 고정된5정책 비교

최초 신호·watch/날짜/route/epoch 경계 및 같은 종목의 비중복 점유를 적용했다. watch를 묶던 기존 방식과의 민감도 비교에서도 이번 자료의 선택 ID 차이는 없었다. 원60분 가격경로·비용·stop을 유지했고10분 이후 목표 도달도 포함했다. 미확정은 손실0이나 성공으로 변환하지 않았다.

### 전체 origin, 각 정책의 관측된 날짜 전체

아래 비율은 **날짜 동일 가중**이다. 단순 전체 건수 비율과 다르며, 후보 사이 관측 날짜가 다를 수 있으므로 이 표만으로 개선을 판정하지 않는다.

| 정책 | 선택 관측 / 완전 경로 | 목표 / 손절 / 완전 미도달 / 미확정 | 비용 후 양수 비율 | 목표·손절 확정 승률 |
|---|---:|---:|---:|---:|
| 기존 정책 B0 | 10 / 10 | 3 / 5 / 2 / 0 | 30.95% | 21.43% |
| 원흡수 A0 | 18 / 17 | 8 / 6 / 3 / 1 | 46.67% | 55.56% |
| 기존 H2 | 17 / 16 | 8 / 5 / 3 / 1 | 50.00% | 61.11% |
| 1틱 이동 | 6 / 6 | 3 / 1 / 2 / 0 | 50.00% | 83.33% |
| 비중복 직전10틱 | 12 / 12 | 3 / 6 / 3 / 0 | 22.22% | 24.44% |

1틱 이동 후보의 두 완전 미도달은60분 종료 기준 비용 후 음수다. 따라서83.33%를 전체 진입의 수익 확률로 해석하면 안 된다. 단순 건수 기준 목표·손절 승률은3/4=75%, 전체 완전 경로 양수는3/6=50%다.

### 동일 날짜 비교와 권고

1틱 이동 후보는9/30에 진입하지 않았다. 이를 승률0으로 대입하거나 기존 진입을 보존해야 한다는 조건으로 탈락시키지 않았다. 비교 가능한9/29·10/2에서 같은 날짜 가중치를 적용했다.

| 공통2날짜 | 기존 정책 B0 | 원흡수 A0 | 1틱 이동 |
|---|---:|---:|---:|
| 완전 경로 | 9 | 13 | 6 |
| 비용 후 양수 비율 | 46.43% | 45.00% | **50.00%** |
| 목표·손절 확정 승률, A0와 후보 공통날짜 | 비교 날짜 부족 | 58.33% | **83.33%** |

원흡수 대비 양수 비율 **+5pp**, 확정 승률 **+25pp**다. 기존 H2의 같은2날짜 양수 비율도50%이므로, 새 후보가 H2의 주지표까지 높인 것은 아니다. 기존 H2보다 신호가 적고 확인된 승패 구성은 다르다.

같은 원 사건·절대 종료시각 비교도 별도로 남겼다. 전체 origin은1틱 이동54사건 중6쌍/48한쪽, 비중복10틱54사건 중24쌍/30한쪽이다. 상시감시는 각각28사건 중3쌍/25한쪽,12쌍/16한쪽이다. 이는 진입시점 진단이며 정책별 barrier 결과나 실제 체결을 대체하지 않는다.

## 4. 상시감시·민감도 한계

상시감시에서1틱 이동 후보가 선택한 것은10/2의3건뿐이다. 목표1·60분 미도달 음수2로, 양수 비율33.33%는 같은 날 원흡수50%보다 낮다. 목표·손절 확정 승률100%는 목표1건만 남은 분모이며, 이 수치로 상시감시 개선을 주장하지 않는다. 비교 가능한 날짜도1개다.

비중복10틱의 상시감시 양수 비율은16.67%로 원흡수50%보다 낮다.

전체1틱 이동의 날짜 제외 분석은9/29 또는10/2를 빼면 비교 날짜가1개가 되어 지원 부족이다.9/30 제외는 원래 공통 비교와 같아 +5pp를 유지한다. 변경된48사건의 개별 제외 중46개는 개선이 남지만,9/29 11:39:13 손절 사건 제외 시 차이0pp,11:58:54 손절 사건 제외 시 -5pp가 된다. `single_event_or_day_sensitive`로 표시했다. 이 자료를 새 독립 holdout으로 승격하지 않았다.

## 5. 코드리뷰·수정보완

1. 새 모듈은 계획의 위치 gate에 따라 `src/engine/scalping`의 오프라인 분석 역할로 작성했다. API 요청/응답 parser 또는 운영 판정 코드를 변경하지 않았다.
2. 최초 실제 입력 재생에서 원본 `krx_regular`을 새 코드가 대문자 리터럴과 비교한 결함을 발견했다. 기존 흡수 판정기와 같은 대소문자 정규화로 수정했다. raw/receipt bytes는 불변이다. 실패한 `run-01`은 결과 없음으로 남겼다.
3. 결과 리뷰에서 “각 정책의 전체 날짜 집합 동일”을 요구하던 불필요한 제한을 발견했다. 계획의 “비교 가능한2날짜”를 구현하도록 공통 날짜의 각 arm을 함께 재집계했다. 진입 없는 날짜와 미확정은 별도 공개하며0으로 채우지 않는다. 가설·임계값·성과 지표·표본 하한을 재탐색하지 않았다. `run-02`는 이 결함이 있던 중간 결과이며 **최종 권고는 `final/`만 사용**한다.
4. 재리뷰에서 정상/거부 조건, 최소11/20tick, 미래/지연 수신, timestamp 동률과 seq, epoch/중복/gap, 수량·방향, 정확한 현재 구간, endpoint TTL, 원본 변조, 비진입 보존, 공통 날짜·미확정 점유·성공 보존 veto 부재를 확인했다.

최종 관련 회귀 **58 PASS**. Python compile·engine 위치 gate·문서 parser·diff 검사를 수행했다. 실제 원천에서 **859개 구간 prefix/직접 수량합 검증**, **1,038개 label 독립 행동 검증**과 사건 묶음 동일성을 확인했다. 기존3대조군의 선택 ID·지표 차이0, 최종54개 source/code SHA 재검증 PASS다. 검토한 범위의 미해결 코드 결함은 없다.

전체 거래 suite·API·신규 원천 수집·실제 매매 재현은 실행하지 않았다. 해당 영역의 운영 무결점이나 수익을 이번 검증으로 주장하지 않는다.

## 6. 종료·보존·다음 소유

- `SamsungContinuousTickWindowResearch`: 두 가설 연구 완료. 후보1개 동결 후 종료.
- `SamsungFrozenCandidateValidation1006`: 원흡수·H2·과거 veto2개와 구분하여 이번 후보를 인계한다. 새 candidate ID는 기존 H2 forward adapter가 소비할 수 없다. **동결 파일에 `forward_adapter_status=not_implemented_for_new_tick_window_definition`을 명시했다.** 새 날짜 검증 전에 현재10tick에 결속된11tick receipt와 원흡수 동작을 검증하는 별도 소비자 연결이 필요하다. 등록 파일 자체를 검증 실행 완료로 표시하지 않는다.
