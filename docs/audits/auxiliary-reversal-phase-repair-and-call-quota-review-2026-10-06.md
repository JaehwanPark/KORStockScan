# 연속 반전 보조 입력·프롬프트 보완과 호출한도 해제 검토 — 2026-10-06

## 1. 완료 범위

보조 연구를 먼저 보완한 뒤 다음 영업일 계획을 수정하라는 지시에 따라, **같은 기존 118개 지점과 새 기계정책에 맞춘 추가 254개 지점, 총 372개(8일·87종목)**에 대한 비교를 완료했다. 이번 실제 추가 호출은 **1,742회**, 이전 390회를 포함한 원 응답은 **2,132개이며 고유 response ID도 2,132개**다. A/C/F/G/H 공통 비교에는 372개 지점마다 5개 실제 응답이 모두 있다. 일자별·가격대별 해시 표본이며 전체 149만 반전을 전부 AI에 호출한 결과는 아니다.

코드는 입력·프롬프트·응답 계약과 운영 AI 횟수 한도 해제까지 수정했다. 새 보조 계약은 아직 운영 consumer에 연결하지 않았다. 배포·정책 발행·오늘 장후 재생성·내일 PID 소비는 아래 계획의 후속 실행 범위이며 이번 연구 완료로 주장하지 않는다.

## 2. 확인한 결함과 보완

- `buy_pressure_10t`, `return_10t_pct`, `vs_vwap_60s_pct`는 첫 상승 틱까지 포함한 누적 창인데 C는 이를 모두 반전 **직전** 상태로 설명했다. 새 입력은 `FIRST_UPTICK`, `rolling_windows_end=AT_TRIGGER`, `post_trigger_observations=NOT_YET_OBSERVABLE`로 구분한다. 관측하지 않은 반전 이후 매도나 재하락을 만들지 않는다.
- 약한 지표의 원 수치·fact ID를 그대로 남기되, 누적 약세와 현재 반전 무효화를 구분했다. 매도 우세·VWAP 미회복 자체가 자동 거부 사유가 되지 않으며, 반대로 이를 긍정 사실로 바꾸거나 모든 반전을 PASS로 고정하지 않는다.
- F는 진입 매도호가 기준 목표·손절 가격, 현재 체결 대비 매도호가 premium과 목표 거리 계산을 추가했다. 비용·스프레드 이중 차감을 금지한다.
- G는 `contradicting_fact_ids`에 문맥상 우려의 근거도 인용할 수 있음을 명시했다. 앞선 후보의 CAUTION + 빈 근거/NO_BLOCKING_RISK 모순을 줄였다.
- H는 필수 원천 검증을 통과한 요청에 `SOURCE_QUALITY_GAP`/`INSUFFICIENT`를 허용하지 않는 schema를 비교했다. 실제 필수 원천 결손은 **호출 전 제외**한다. H가 G보다 승률이 높아진 것은 아니므로 최신 버전이라는 이유로 전체 교체하지 않는다.

[공통 순수 계약 구현](../../src/engine/scalping/reversal_auxiliary_contract.py)은 `src/engine/scalping`이 소유한다. provider 호출·정책 writer·주문 기능은 없다. [실제 호출 runner](../../tmp/auxiliary-reversal-phase-repair-20261006/run_research.py)는 기존 OpenAI executor, `gpt-5.4-nano`, HTTP, reasoning `none`, `store=false`, 출력 최대 512토큰을 그대로 사용한다. [OpenAI Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 schema 지원과 의미 검증 분리 원칙을 확인했다. 정상 JSON도 의미 모순이 있을 수 있어 로컬 검증 결과를 별도로 보존했다.

## 4. 패턴과 시장별 차이

**매수수량 비중 <40% AND VWAP 아래**인 105개(승리 95개)에서 A는 PASS가 없었다. C는 51/55승(92.7%, 실패 PASS 4개), G는 **61/65승(93.8%, 실패 PASS 4개)**다. G는 같은 실패 통과 수에서 승리 10개를 추가로 통과시켰다. H는 49/54승(90.7%)으로 더 좋지 않았다. 이 교집합은 연구 패턴이며 새 진입 필수 AND gate로 추가하지 않는다.

372개 전체의 삼성 정규에서 C는 12/14승(85.7%), G는 17/18승(94.4%)이다. 삼성 애프터는 C 8/24승(33.3%), G 7/23승(30.4%)로 나빠졌다. 비삼성은 정규 C 53/63승(84.1%)→G 57/65승(87.7%), 애프터 35/56승(62.5%)→40/62승(64.5%), 프리 42/55승(76.4%)→45/59승(76.3%)다. 따라서 G 전체 복사가 아니라 시장·유형별 실제 PASS 승률을 비교한다.

## 6. 호출한도 영구 해제

운영 [공용 호출 계수기](../../src/engine/ai/hot_path_ai_symbol_budget.py)의 기본값을 `total_cap=None`, `group_cap=None`으로 바꿨다. 과거의 종목당 60초 4회/endpoint group 2회 제한과 이를 재설정하는 예전 환경변수는 운영 기본 경로에 적용되지 않는다. 재기동 후에도 이 기본값을 쓰며 만료일이 없다. Main entry·holding·scale-in 소비와 `None` snapshot의 과거 재생 호환을 확인했다. 명시적 유한 quota 인수는 과거 offline replay fixture에만 남긴다.

호출 계수·예약·정확한 예약 반환·입력 식별·중복/재시도 간격은 유지한다. provider 자체 rate limit, 동시 처리·timeout·오류 retry 제한은 호출 총량 quota와 구분한다. 브로커 요청·주문·자본 cap은 변경하지 않는다. 실제 실행 PID 반영은 최종 release 배포/기동 receipt로 확인해야 한다.

이번 오프라인 연구에는 호출 수/일일 비용/부모 표본 quota를 적용하지 않았다. 과거 390회 ledger와 원 해시를 보존하고 새 **무제한 승인 명세 + 단일 worker lock + 호출 전 fsync 예약 + 응답/토큰 영수증**으로 수행했다. 처리 동시성은 4이며 무제한 동시 요청이라는 의미는 아니다. 당일 구 장부를 지우거나 0회로 초기화하지 않았다. 불확실한 전송을 자동 재호출하지 않는다. 새 장후 보조 producer도 이 무제한 승인·계수 계약으로 전환하는 것이 후속 구현 범위다. 구 postclose 경로의 390회 제한이 이미 배포에서 제거됐다고 주장하지 않는다.

이번 추가 호출 입력 2,953,334토큰·출력 146,835토큰. 실제 청구금액은 이번 집계에서 계산하지 않았다. 계수상의 0 비용을 무료 호출로 쓰지 않는다.

## 7. 검증과 남은 실행

수정→self review→인용/필수 원천 schema 보완→재리뷰를 진행했다. 입력 미래정보 차단·원 숫자 보존·진입가격 수식·필수 결손 선제 제외·잘못된 PASS 자동변환 금지·예전 env로 운영 quota 재활성화 방지·500회 연속 호출 계수·남은 중복 간격·소비자 예약 반환을 검사했다. 대상 회귀는 **64 PASS**(격리 계약/관련 handler 20, holding/rising 소비자 33, 기존 연구 11)다. compile과 diff 검사도 수행했다.

큰 `test_sniper_scale_in.py` 전체를 함께 실행한 첫 시도는 테스트 비동기 worker의 `psycopg2.connect`에서 native segmentation fault로 중단됐다. 이 전체 suite를 PASS라고 보고하지 않는다. 이후 이번 변경과 직접 연결되는 사례를 격리해 위 64개를 검증했다. 광범위 suite의 외부 DB/비동기 worker 격리는 이 연구의 완료 증거가 아니다.

[다음 영업일 적용 계획](../proposals/continuous-reversal-machine-policy-nextday-plan-2026-10-06.md)에 후보 확정, 정규장 승계, 장후 기계/보조 producer 전환, 최종 release, EOD 제외 전체 장후 재생성, strict/controller/finalization과 다음날 준비/실기동 확인을 연결했다. 이번 연구 worker의 실제 호출 외에 장후 wrapper·정책 publisher·봇 재기동은 실행하지 않았다.
