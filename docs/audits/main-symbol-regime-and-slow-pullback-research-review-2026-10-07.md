## 1. 요청별 결론

1. **삼성 새 눌림은 누적 원천으로 확인한 정책이다.** 다만 발행 당시의 32/32는 9/29에 27점, 10/2에 2점, 10/7 오전에 3점으로 집중돼 있었다. 독립 거래 32회의 성공이 아니다.
2. 오늘 오후까지 고정 원천을 확장하자 같은 native 조건은 **32/33(96.97%)**으로 바뀌었다. 10:15의 한 확인점은 같은 item 완성 분봉 보완에서 30분 목표 미도달로 확정됐다. 정책 첫 적용 12:34 이전의 연구 사례이며 실제 운영 손실이 아니다. 더 작은 낙폭·느린 상승을 단순 확대한 후보는 아직 이 승률을 넘지 못했다. 기존 체결 비율을 쓰는 정제 후보는 별도로 나왔다.
3. 두산·HPSP·알테오젠·주성은 다른 패턴을 보인다. HPSP·알테오젠·주성의 신규 연속 원천은 오늘에 집중되므로 과거 여러 날의 종목별 검증으로 표현하지 않는다.
4. 일반 비삼성을 576개 관측 유형으로 분리했다. 완성 특징 유형은 388개이며 UNKNOWN 188개는 관측 상태다. 후속 비교한 네 유형의 첫 반전을 기존 규칙과 합치면 중복 제거 후 **확정 목표 88점과 미확정 70점**이 추가된다. 같은 연구 범위의 누적 승률은 **81.9913%→82.0354%, +0.0441%p**다. 큰 성능 개선이나 실제 주문 증가는 입증하지 않았다.

이번 요청에서 운영 정책·코드·selector·PID·provider·주문을 변경하지 않았다. 누적 raw 승률 비교에 최소 표본/일수·holdout·EV·성공 100%/80% 보존 조건을 추가하지 않았다.

## 3. 삼성: 누적 정책의 원래 의미와 새 관측

### 3.1 원 정책 발행 시점

[당시 source](../../data/report/continuous_reversal_v2/2026-10-07/source.json)는 8개 과거 날짜와 오늘 오전 접두를 검사했다. native item을 통과한 등록 branch는 9/29 **27 WIN**, 10/2 **2 WIN**, 10/7 오전 **3 WIN**으로 32/32였다. 과거 날짜 모두에서 성공 표본이 있었다는 의미는 아니다. 32점은 목표 접촉 clock **6개**로 겹치며 오늘 3점도 같은 목표 접촉이다.

현재 `samsung_up_shallow_next_up_5_v1`은 직전 하락 ≤0.4%, 과거 5분 낙폭 0.4~0.8%, ret60≥0.2%, 첫 세션 관측 대비 ≥0.4%, 최근 30초 저점 상승을 첫 반전 때 확인하고, 원 저점 재접촉 전에 5초 안의 다음 상승에서 확정한다. 5분은 최대 lookback이며 필수 warm-up 시간이 아니다.

## 6. 신호→평가 지연: 정책 희소와 전달 지연의 구분

위 clock 있는 정상 capture에서는 5초 초과가 0이다. 정상 경로만의 통계로 전체 전달이 정상이라고 판단하지 않았다. 새 clock 계측 v2 거절은 다음과 같다.

- **삼성 4건:** 신호→validation 0.027~0.676초, 모두 `FIRST_UPTICK`이 최신 첫 반전과 달라져 무효. validation→lock 내부 state 관측은 0.114~0.578초다. 짧은 시간에도 첫 반전이 교체될 수 있다. 이를 단순 5초 만료나 API 원천 결손으로 묶지 않는다.
- **HPSP 4건:** 신호→validation 6.011~9.470초, `reversal_signal_expired`. 실제 관측된 신호 전달/평가 만료다.
- **주성 1건:** 0.484초 뒤 첫 반전 무효. 알테오젠 1건은 원 stored claim이 없어 `generation_changed`; 현재 정책이 실제 바뀌었다는 증거는 아니다.
- 구 v1 receipt는 이전 validation clock 결함 때문에 현재 정량 지연 통계에서 제외했다. 과거 거절 count는 원인별 이력으로 보존했다.

코드상 [WATCHING](../../src/engine/sniper_state_handlers.py:50160)은 claim을 먼저 잡고, [평가 준비](../../src/engine/sniper_state_handlers.py:63069)는 tick history·candle·investor context·입력 refresh를 거쳐 [AI engine 안의 기계 검증](../../src/engine/ai_engine_openai.py:9541)으로 전달한다. 이 사이에 5초 예산을 소모할 수 있다. 이번 자료에는 claim 생성 clock과 각 준비 호출의 start/end를 같은 attempt에 묶은 완전한 기록이 없으므로 **6~9초 전부를 특정 API/HTTP/WS 지연으로 단정하지 않았다.**

삼성의 오늘 새 등록 branch는 적용 이후 cutoff까지 확인점 자체가 0이고, 새 v2 거절 4건은 모두 FIRST다. 따라서 오늘 삼성 ENTER_NOW=0을 '좋은 확정 눌림 신호가 계속 전달 지연으로 사라졌다'고 해석할 증거는 없다. 지금은 조건 희소와 FIRST 교체를 별도로 해결해야 한다.

## 7. 후속 구현 우선순위와 경계

1. **전달 계약:** same-attempt claim 생성→준비 start/end→validation을 연결하고, 오래된 pending claim이 준비 뒤에도 전달되는 경로를 보완한다. native latest claim을 다시 평가하는 방식은 exact 입력·quote·generation·중복 intent를 함께 검증해야 한다. FIRST 교체 guard 또는 5초 TTL을 완화하는 계획이 아니다.
2. **종목별 병행 branch:** HPSP 0.4~0.8 상승 눌림, 알테오젠 깊은 DD 후 느린 반등, 주성 작은 느린 상승을 서로 다른 symbol scope로 정의한다. 현재 volume 계산을 stale 행 합산으로 복구하지 않는다. 새 branch는 자기 필수 특징·확정 clock·입력 해시와 같은 비용/라벨을 갖는다.
3. **삼성:** 작은/느린 확대는 이번 범위에서 우위를 확보하지 못했다. 현 눌림 + 10틱 매수≥60%의 18/18 정제 후보와 DD 0.4~0.8/VWAP 후보를 producer와 consumer의 동일 규칙으로 구현할 수 있게 비교한다. 표본/보존 문턱으로 배제하지 않는다. 현재 32/33을 다음 native 장후 생성이 실제로 소비하는지도 확인한다.
4. **일반 비삼성:** 네 유형을 자동 생성기의 세분 후보로 넣을 수 있도록 native 특징 정의·symbol 제외·같은 item·OR 중복·확인 phase·가격대 selector의 구조를 설계한다. 같은 원천에서 +0.0441%p였다는 비교를 유지하며 추가 sample을 실제 거래 수로 표현하지 않는다.

원천은 더 조회하지 않았다. 이번 연구는 기존 자료에서 확인 가능한 가설을 확장한 결과다. 정책 activation이나 실제 미래 승률은 별도이며 운영 반영은 이번 문서로 실행되지 않았다.
