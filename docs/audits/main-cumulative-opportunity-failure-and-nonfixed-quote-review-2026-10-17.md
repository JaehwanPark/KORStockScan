## 1. 결론

실행 계획은 [두 축 및 호가 정합성 연구 계획](../proposals/main-cumulative-opportunity-and-executable-quote-research-plan-2026-10-17.md)이다. 추가 탐지 A17~24 8개, 실패 감소 F23~30 8개, 기존형·정제형·추가형·결합형 50,688개 표현을 실제 누적 원천으로 계산했다. 같은 membership의 별칭이 포함되어 있으므로 50,688개의 독립 통계 검정으로 부르지 않는다.

핵심 판단은 다음과 같다.

1. **비상시감시의 진입 확인점에 stale 호가가 섞여 연구 성과를 높였다는 증거는 없다.** 기존 현재 정책 CF 150개, 신규 포함 166개, 신규 A 포함 전체 20,248개 확인점의 관측 최우선 호가 age는 모두 700ms 이내였다. 0D 잔량·미시구조·native 출처 전체와 제출 시점의 신선함까지 검증된 것은 아니다.
2. **실시간 감시·제출 가능성을 평가하는 관측 범위는 부족하다.** 실제 명시적 Main ENTER 2,927개 중 비상시감시는 1개이고 사후 가격 적격 연결도 결손이다. 감시 편입 전 종목, 준비 단계에서 탈락한 기회, AI 이후 quote 소비는 이 분모에 없다.
3. **지연에 대한 취약성 차이는 확인됐다.** 과거 보존 0B 틱에서 3초 후에도 신선한 호가를 확인할 수 있는 하한은 비상시 33.3%, 상시 88.6%다. 별도 0D 전체 수신을 재생하지 않았으므로 실제 stale 거절률은 아니다.
4. **새 패턴은 제한적인 추가 기회를 제공한다.** 두산 정규장의 A19, 비상시 고가 PRE의 A22에서 각각 현재 대비 목표 선도달 확인점 1개를 추가했다. 모두 OR하면 미도달도 크게 늘어 scope별 선택이 필요하다.
5. **실패 감소 후보에는 성공 기회 축소가 있다.** 누적 승률 우선안의 CF는 70.36%→71.75%지만 목표 확인점은 909→899개다. 기회 확대 대안은 70.86%, 목표 912개다. 두 안을 운영 적용하거나 실현 손익 개선으로 보고하지 않는다.

## 6. 비상시감시의 데이터 충분성·quote stale 질문

### 연구 입력과 실제 제출 기준의 관계

연구 [good_quote](../../src/engine/scalping/continuous_reversal.py:26)는 quote age 미기록 또는 5,000ms까지 허용한다. 실제 AI 입력 전 canonical quote의 기본 3,000ms, [latency 분류](../../src/trading/entry/latency_monitor.py:24)의 SAFE 기본 250ms·CAUTION 기본 700ms는 역할이 다르다. 환경 override와 실제 PID 유효값은 별도 증거다. 두 latency 상태 모두 다른 안전조건을 통과하면 정상 제출 경로를 사용할 수 있다.

넓은 연구 허용 범위는 존재하지만 **현재 및 신규 연구 확인점에 오래된 호가가 섞였다는 가설은 이번 전수 대조에서 확인되지 않았다.** [quote profile](../../tmp/main-machine-cumulative-dual-track-research-20261017/source/quote-new-profile.json)의 신규 포함 현재 CF 비상시 166개는 W78/STOP4/TIMEOUT18/U66이며 모두 확인점 age≤700ms다. 전체 유효 비상시 raw 1,603,744행은 가격 특징 연구용 데이터지만 모든 시장 기회·모든 감시 편입 상태를 대표하지 않는다.

확인점 age는 최우선 bid/ask의 관측 상태다. inline 0B의 최우선 호가가 fresh여도 별도 0D 잔량·미시구조가 누락되거나 native 출처 증빙이 부족하면 실제 준비가 차단될 수 있다. 연구의 가격 데이터 충분성과 실시간 제출 준비 증빙의 충분성을 구분해야 한다.

### 지연 시나리오를 새로 검증한 결과

[호가 지연 진단](../../tmp/main-machine-cumulative-dual-track-research-20261017/source/quote-delay-profile.json)은 과거 현재 CF 9,502개에서 entry+0/1/2/3초까지 받은 마지막 0B prefix만 사용한다. 미래 틱이 가진 0D 추정 시각을 과거로 역투영하지 않으며, 0초 확인 시점에는 같은 timestamp의 다음 sequence도 빌려 쓰지 않는다.

| 확인 후 시간 | 비상시: 700ms 신선함을 확인 가능한 하한 / 150 | 상시: 같은 기준 / 9,352 |
|---|---:|---:|
| 0초 | 150 (100%) | 9,352 (100%) |
| 1초 | 67 (44.7%) | 8,255 (88.3%) |
| 2초 | 59 (39.3%) | 8,221 (87.9%) |
| 3초 | 50 (33.3%) | 8,283 (88.6%) |

## 7. 제출 기회를 늘리기 위한 후속 구현안

호가 TTL 완화나 결손을 fresh로 간주하는 방식으로 추진하지 않는다. **비상시의 준비 시점·호가 수신·평가 소비를 같은 기회에 맞추는 작업**을 다음 우선순위로 인계한다.

1. **같은 기회의 시간과 원천을 연결한다.** 기존 producer/consumer에 남는 promotion/편입, 원 신호, 가격/0D 준비, machine, AI 시작·끝, Main claim, 제출 직전 호가의 item/epoch/sequence/시각·deadline·거절 사유를 exact evaluation/intent로 대조한다. top quote·depth quote·체결 clock을 분리한다. 판정 전 결손과 제출 전 만료의 분모도 분리한다.
2. **감시 편입 단계에서 기존 준비를 완료한다.** 비상시 편입 후 0B·0D와 기존 rolling cache·source receipt가 준비되었는지 확인한다. 무신호 전 종목 REST prefetch나 새 수집 축을 확대하지 않는다. 구독·회복 프로토콜을 변경할 구현은 공식 Kiwoom reference gate를 먼저 거친다.
3. **신선한 호가가 도착하면 즉시 평가·소비한다.** source-ready event를 기존 경로로 전달하고 준비·평가 큐의 오래된 snapshot 대기를 줄인다. 아직 유효한 원 신호의 기존 deadline 안에서만 현재 특징·현재 ask로 기계판정을 다시 수행하고 intent를 dedup한다. 만료 신호를 되살리지 않는다.
4. **PASS 뒤 재확인을 연결한다.** 현재 quote·route·epoch·가격·수량과 기존 PASS 재사용 계약을 검사한다. quote 갱신만으로 과거 AI 응답의 입력을 바꾸거나 expired PASS를 재사용하지 않는다. 제한된 정상 재확인 뒤에도 신선한 증빙이 없으면 기존 안전 차단을 유지한다.
5. **비상시 유형을 실행 특성과 함께 평가한다.** 현재 가격대·세션 분류에 관측 prefix상의 체결 간격, 호가 갱신 증거, 편입 후 준비 상태를 진단 변수로 붙인다. 빈번 체결형·간헐 체결형·편입 직후를 나누되 미래 체결 빈도로 진입 시점 유형을 정하지 않는다. 위 179880의 깊은 회복 성공·초기 하락 실패도 별도 수동 가설로 다룬다.
6. **완료 기준:** stale/missing guard·기존 기계/보조판정·수량·custody·provider 권한을 유지하면서 exact 기회의 준비시간/claim 지연을 줄이고, 같은 신호가 fresh quote 및 정상 제출 호출까지 연결되는지를 확인한다. 거절 사유만 새로 세분하거나 CF 목표 수 증가만으로 완료하지 않는다. 실제 broker/체결/비용 성과는 그 다음 단계다.

이번 작업은 연구·구현 인계 계획까지 완료했다. 위 runtime 개선은 구현·등록·배포 대기이며 이번 연구에서 실행하지 않았다.
